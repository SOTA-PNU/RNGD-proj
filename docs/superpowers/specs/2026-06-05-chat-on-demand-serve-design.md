# RNGD Chat — 모델 on-demand serve + 상태 LED 설계

작성일: 2026-06-05
대상: `Model_Benchmark/rngd-npu/chat/`(Gradio 채팅 UI `chat_app.py`, 모델 서버 스크립트 `serve_models.sh`)

## 1. 목적

지금 chat 서비스는 `serve_models.sh`로 모델을 미리 띄워야만 쓸 수 있습니다. 가벼운(tp8) 모델은
카드 1장씩 최대 4개를 미리 올려둘 수 있지만, 무거운(tp32) 모델은 카드 4장을 다 써야 해서 미리
같이 올려둘 수 없습니다. 그래서 **드롭다운에서 모델을 고르면 그 순간 필요한 만큼 카드를 비우고
serve를 시작**하고, **각 모델이 지금 떠 있는지 한눈에 보이게 상태 LED**를 띄우는 방식으로 바꿉니다.

## 2. 핵심 제약(설계를 강제하는 사실)

- furiosa-llm serve는 가중치를 NPU HBM에 통째로 올려서 **로딩에 수 분** 걸립니다(33GB급은 더). 즉
  선택 즉시 serve해도 사용 가능(🟢)까지 수 분 대기합니다.
- 카드 4장. **tp8=1장, tp32=4장 전부.** 무거운 모델을 고르면 가벼운 것 포함 기존 serve를 전부 내려야
  합니다(불가피).
- 일부 모델은 serve가 실패합니다: Qwen3-Coder-30B-A3B(FP8 MoE 커널 없음, 패닉)는 드롭다운에서 제외.
  Qwen3-32B-FP8 계열은 뜨지만 매우 느리고 tp8은 NPU `Unknown error -5`로 죽은 이력이 있어, serve
  실패·조기 종료를 감지해 빨간불로 처리해야 합니다.

## 3. 동작 결정(합의됨)

- **트리거**: 드롭다운에서 모델을 고르는 즉시 serve 시작(논블로킹).
- **가벼운 모델 정책**: tp8 모델은 최대 4개까지 계속 띄워둠(warm). 무거운(tp32) 모델을 고를 때만
  전부 내림. tp8을 골랐는데 빈 카드가 없으면 가장 오래 안 쓴 tp8 하나만 내리고 그 카드를 씀.
- **로딩 중 전송**: 대상이 아직 🟡(로딩 중)일 때 메시지를 보내면, 준비될 때까지 기다렸다가 자동으로
  답합니다(사용자가 다시 보낼 필요 없음).
- **LED 3색**: 🟢 떠 있음(요청 처리 가능) / 🔴 안 떠 있음(또는 serve 실패) / 🟡 올라가는 중·내려가는 중.

## 4. 구조

### 4.1 공유 모델 카탈로그

8개 servable 모델 정의를 한 곳에 둡니다(키, 표시이름, 포트, tp=카드수, 아티팩트 경로, 추가 serve 인자).
`chat_app.py`의 `ServeManager`와 상태 표시가 이 카탈로그를 읽습니다. `serve_models.sh`는 수동 CLI
폴백으로 유지하며 같은 포트·아티팩트·옵션을 씁니다(둘이 어긋나지 않게 동일하게 관리).

| 키 | 포트 | tp(카드) | 모델 |
|---|--:|---|---|
| coder1.5 / coder7 / coder14 | 8001~8003 | tp8(1) | Qwen2.5-Coder 1.5B/7B/14B |
| qwen3-32b / qwen3-32b-16k | 8004~8005 | tp8(1) | Qwen3-32B-FP8 / 16K |
| exaone-32b / llama-70b / qwen3-32b-tp32 | 8011~8013 | tp32(4) | EXAONE-4.0-32B / Llama-3.3-70B / Qwen3-32B-tp32 |

Qwen3-Coder-30B-A3B-FP8은 serve 불가라 카탈로그·드롭다운에서 제외(주석으로 사유 명시).

### 4.2 ServeManager (신규, `chat_app.py` 내)

모델별 상태 머신과 furiosa-llm serve 서브프로세스 라이프사이클을 관리합니다. 동시 접근을 막는 락 하나를 둡니다.

상태: `down` / `loading` / `up` / `stopping` / `error`. LED 매핑은 down·error→🔴, loading·stopping→🟡, up→🟢.

- `request(model)`: 드롭다운 선택 시 호출(논블로킹, 즉시 반환).
  - 이미 `up`이면 아무것도 안 함.
  - tp32 모델이면: 다른 모든 serve를 `stopping`으로 두고 내린 뒤(카드 4장 확보) 대상 `start`.
  - tp8 모델이면: 현재 tp32가 떠 있으면 그 tp32를 먼저 내려 카드를 비움. 그다음 빈 카드가 있으면 그
    카드로 `start`, 없으면(tp8이 4장 다 참) LRU tp8 하나를 stop 후 그 카드로 `start`.
  - `start`는 백그라운드 스레드에서 `furiosa-llm serve <artifact> --devices <dev> --port <port>
    --enable-prefix-caching <extra>`를 띄우고, `/v1/models`가 200이 될 때까지 폴링 → `up`. 정해진
    시간(기본 900초) 안에 못 뜨거나 프로세스가 먼저 죽으면 → `error`(로그 경로·사유 기록).
- `stop(model)` / `stop_all()`: SIGTERM으로 내림(필요 시 SIGKILL). 카드 반환.
- `states()`: 모델별 LED 상태 반환. `up` 판정은 추적 상태 + 실제 포트 200 프로빙을 함께 봐서, 외부에서
  죽은 경우도 🔴로 반영.
- `wait_until_up(model, timeout)`: 전송 시 로딩 대기에 사용.

카드 배정은 카탈로그의 tp 값으로 결정(tp8=1, tp32=4). 락 안에서 빈 카드 집합을 관리.

### 4.3 UI 변경 (`chat_app.py`)

- **상태 패널**: 모델 목록 + 각 LED를 보여주는 `gr.HTML`. `gr.Timer`(약 3초)로 주기 갱신 —
  `ServeManager.states()` + 포트 프로빙 결과로 색을 칠함. 어느 카드를 쓰는지도 같이 표기.
- **드롭다운 `.change()`** → `ServeManager.request(선택모델)` 호출(즉시 🟡). 화면은 안 멈춤.
- **`chat_fn`**: 생성 직전 대상이 `up`이 아니면 → `loading`이면 `wait_until_up`으로 대기 후 진행,
  `down`이면 `request` 트리거 후 대기, `error`면 사유를 출력하고 중단. 이후 기존처럼 스트리밍.
- 종료 시(앱 내림) 떠 있는 serve를 정리할지는 옵션(기본은 유지 — Continue 등과 공유 가능).

## 5. 데이터 흐름

```
드롭다운 선택 ─▶ ServeManager.request(model)
                   │ (락) 카드 예산 계산: tp32면 stop_all, tp8면 빈 카드/ LRU
                   ▼
              백그라운드 스레드: furiosa-llm serve 서브프로세스 + /v1/models 폴링
                   │
        gr.Timer(3s) ─▶ states() ─▶ 상태 패널 LED 갱신 (🔴→🟡→🟢)

메시지 전송 ─▶ chat_fn ─▶ (대상 up 아니면 wait_until_up) ─▶ /v1/chat/completions 스트리밍
```

## 6. 에러·엣지 처리

- serve 실패(패닉/타임아웃/프로세스 조기 종료) → `error`(🔴), 패널·채팅에 사유와 로그 경로 안내.
- 무거운 모델 선택 시 가벼운 것들이 내려가는 과정을 LED(🟢→🟡→🔴)로 보여줘 사용자가 인지.
- 드롭다운 빠른 연속 변경 → 락으로 직렬화. 전환 진행 중 다른 모델 선택 시 진행 중 전환을 정리하고
  새 대상으로 전환(또는 "전환 중" 안내). 단순화를 위해 한 번에 하나의 전환만 진행.
- 외부에서(예: serve_models.sh, 벤치) 같은 카드를 점유 중이면 start 실패 → `error`로 표면화.

## 7. 테스트

- 단위/스모크(서버 없이): 카탈로그 로드, 카드 예산 계산(tp8 4개 한도·tp32 단독·LRU 교체) 로직,
  상태→LED 매핑, 서버 0개일 때 패널이 안 죽는지.
- 가드: 알 수 없는 모델, serve 실패 시뮬레이션(가짜 포트), 로딩 중 전송 대기.
- 라이브(카드 사용): 가벼운 2개 동시 → 둘 다 🟢, 전환 즉시 응답. 무거운 1개 선택 → 가벼운 것들
  🔴로 내려가고 무거운 게 🟢 된 뒤 응답. (수 분 로딩이라 수동 확인 단계로 분리.)

## 8. 범위 밖(YAGNI)

- 다중 사용자 동시성(개인 도구 전제 — 카드를 공유하므로 한 사용자 기준).
- serve_models.sh를 카탈로그 JSON으로 완전 통합(지금은 양쪽 동일 유지로 충분).
- 모델 자동 사전로딩·예열 스케줄링.
- 대화 저장/불러오기 개선(현 기능 유지).
