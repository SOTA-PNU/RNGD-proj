## 1. 언어 모델이 하는 일: "다음 단어 맞히기"

ChatGPT 같은 언어 모델이 하는 일은 한 문장으로 줄일 수 있습니다. **앞에 나온 단어들을 보고
다음에 올 단어 하나를 확률로 예측하는 것**입니다.

```
입력:  "오늘  점심에  김치"
                          ↓ (모델이 다음 단어 후보에 확률을 매김)
        찌개   62%
        볶음밥 18%
        전     9%
        ...
                          ↓ (가장 그럴듯한 걸 고름)
출력:  "찌개"
                          ↓ (붙여서 다시 입력으로)
입력:  "오늘  점심에  김치  찌개"  →  다음 단어 예측 ...  (반복)
```

이렇게 한 단어를 고르고, 그 단어를 문장 끝에 붙이고, 다시 전체를 보고 다음 단어를 고르는
일을 끝까지 반복해서 긴 글을 만듭니다. 이 한 번의 예측을 "한 스텝", 만들어 내는 단어 하나를
"토큰"이라고 부릅니다.

여기서 **토큰**을 정확히 짚고 갑시다. 모델은 "단어" 단위가 아니라 "토큰" 단위로 봅니다.
토큰은 단어보다 잘게 쪼갠 조각일 때가 많습니다. 예를 들어 영어 "unbelievable"은 한 단어지만
`un` + `believ` + `able` 세 토큰으로 쪼개질 수 있습니다. 이렇게 자주 나오는 글자 덩어리를
미리 사전에 등록해 두고, 글을 토큰 번호의 나열로 바꿉니다.

```
"점심"  --토크나이저-->  토큰 번호 4521
"먹다"  --토크나이저-->  토큰 번호  892
                          (Qwen3-Coder-Next의 토큰 사전 크기 = 151936개)
```

문제는 "다음 토큰"이 바로 앞 토큰 하나로 정해지지 않는다는 점입니다. "나는 어제 산 빨간
자전거를 친구에게"까지 봤다면, 다음을 잘 맞히려면 멀리 있는 "자전거"와 "친구"를 동시에
떠올려 연결해야 합니다. 즉 **문장 안에서 멀리 떨어진 토큰끼리도 서로 참고**할 수 있어야
합니다. 이 "서로 참고하기"를 잘하려고 나온 기술이 어텐션입니다.

## 2. 단어를 숫자로: 임베딩 공간

컴퓨터는 "찌개"라는 글자를 직접 다루지 못합니다. 그래서 토큰 하나를 **숫자 여러 개가 늘어선
벡터**(긴 숫자 목록)로 바꿔서 다룹니다. 이 벡터를 **임베딩(embedding)**이라고 합니다.

```
토큰 번호 4521  --임베딩 표에서 그 줄을 꺼냄-->  [0.12, -0.83, 0.05, ... , 0.41]
                                                 └──── 숫자 2048개 (벡터) ────┘
                              (Qwen3-Coder-Next는 한 토큰을 숫자 2048개로 표현)
```

임베딩 표는 거대한 표입니다. 줄(행)이 토큰 종류 수(151936줄), 칸(열)이 벡터 길이(2048칸)인
표이고, 토큰 번호로 그 줄을 꺼내 옵니다. 이 표의 숫자들은 학습으로 정해집니다.

핵심은 **비슷한 뜻의 토큰이 비슷한 벡터를 갖도록 학습된다**는 점입니다. 그래서 벡터를 점으로
찍으면 뜻이 가까운 단어끼리 가까이 모입니다. 2048차원 공간은 그릴 수 없으니 2차원으로
줄여 상상하면 이런 느낌입니다.

```
   임베딩 공간 (실제로는 2048차원, 그림은 2차원으로 축소)

        고양이 •        • 강아지
                \      /
                 • 동물
   왕 •───────────────• 여왕
   │  (왕 − 남자 + 여자 ≈ 여왕,                     • 바나나
   │   방향과 거리에 뜻이 담김)                    • 사과
   남자 •──────────────• 여자                  (과일끼리 가까이)
```

이게 왜 중요할까요? 모델이 단어를 "기호"가 아니라 "위치와 방향이 있는 점"으로 다루기
때문에, "왕과 여왕은 비슷하다", "왕에서 여왕으로 가는 방향은 남자에서 여자로 가는 방향과
같다" 같은 관계를 숫자 계산(덧셈·뺄셈·내적)으로 다룰 수 있습니다. 어텐션의 "두 단어가 얼마나
관련 있나"도 결국 이 벡터들의 계산입니다.

## 3. 어텐션 이전: 순환신경망(RNN)과 그 한계

어텐션이 나오기 전에는 **RNN(순환신경망)**을 주로 썼습니다. RNN은 문장을 왼쪽부터 한 토큰씩
읽으면서, 지금까지 읽은 내용을 **기억 상자 하나(상태 벡터 h)**에 요약해 들고 다닙니다. 새
토큰을 읽을 때마다 그 기억 상자를 조금씩 갱신합니다.

수식으로는 이렇게 씁니다. 어렵지 않습니다.

```
h_t = f( h_{t-1},  x_t )
       └옛 기억┘  └새 입력┘
새 기억 = 함수(옛 기억, 새로 들어온 토큰)
```

그림으로 펼쳐 보면(이걸 "시간 방향으로 펼친다"고 합니다):

```
 x1      x2      x3            x100
  │       │       │              │
  ▼       ▼       ▼              ▼
[h1] ─→ [h2] ─→ [h3] ─→ ... ─→ [h100] ─→ 다음 단어 예측
  하나의 기억 상자를 계속 덮어쓰며 오른쪽으로 전달
```

RNN의 두 가지 큰 약점이 어텐션을 낳았습니다.

**약점 1: 앞쪽 내용을 잊습니다(기울기 소실).** 기억 상자 크기가 정해져 있어서, 문장이
길어지면 앞 토큰 정보가 뒤로 갈수록 흐려집니다. 왜 흐려지는지 그림으로 보면, x1 정보가
h1에서 h100까지 가는 동안 함수 f를 99번 거치는데, 그때마다 조금씩 곱해지고 섞여서 점점
약해집니다.

```
x1 정보가 h 안에서 남아 있는 정도 (오른쪽으로 갈수록 옅어짐)
h1:████  h2:███  h3:██  h10:▒  h50:░  h100: (거의 사라짐)
```

수학적으로는, 옛 정보가 뒤로 전달될 때 1보다 작은 수가 계속 곱해져 0에 가까워집니다(이걸
기울기 소실이라고 합니다). 그래서 RNN은 100단어쯤 떨어진 두 단어를 연결하기 어렵습니다.

**약점 2: 느립니다.** 토큰을 순서대로 하나씩 처리해야 합니다. h2를 구하려면 h1이 먼저
필요하고, h3은 h2가 필요합니다. 그래서 한 문장을 한꺼번에 동시 계산하기 어렵습니다. 요즘
GPU·NPU 같은 가속기는 수천 개 계산을 동시에 할 때 빠른데, RNN은 줄 세워 계산해야 해서 그
장점을 못 살립니다.

이 두 약점(멀리 못 봄 + 느림)을 한 번에 푼 것이 어텐션입니다.

## 4. 어텐션의 핵심: "필요한 단어를 직접 골라 본다"

어텐션의 발상은 단순합니다. 다음 단어를 맞힐 때, 앞 단어들을 흐릿한 요약 하나로 뭉뚱그리지
말고 **그때그때 필요한 단어를 직접 골라 보자**는 것입니다. RNN처럼 기억 상자에 욱여넣고
흐려지길 기다리는 대신, 필요한 과거 토큰으로 직접 연결선을 긋습니다.

```
나는   어제   산   빨간   자전거를   친구에게   [다음?]
 │                          └─────────────────────┘
 │                          "친구에게" 다음을 맞힐 때
 │                          "자전거를" 에 직접 연결 (거리가 멀어도 한 번에)
 └── 필요하면 맨 앞 "나는" 에도 직접 연결 가능
```

거리가 멀어도 연결이 한 번에 일어나므로 정보가 흐려지지 않습니다(약점 1 해결). 그리고 모든
토큰이 동시에 서로를 볼 수 있어서 한꺼번에 계산됩니다(약점 2 해결). 그럼 "어떻게 고를지"를
정하는 게 핵심인데, 그게 다음 절의 Q·K·V입니다.

## 5. Q·K·V와 softmax: 도서관 비유 + 실제 계산

어텐션을 도서관에서 자료 찾기에 비유하면 딱 맞습니다.

```
       내 질문(Query)              책 색인표(Key)            책 내용(Value)
   "자전거 누구 줬지?"   ──비교──>  [자전거 색인]  ──연결──>  "친구에게"
                                    [날씨 색인]              "맑음"
                                    [음식 색인]              "김치찌개"
   질문과 색인표가 잘 맞을수록 그 책 내용을 많이 가져옴
```

- **쿼리(Query, Q)**: 지금 내가 알고 싶은 것. "친구에게" 다음을 맞히려고 던지는 질문.
- **키(Key, K)**: 각 토큰이 내건 "나는 이런 정보요" 라는 색인표.
- **밸류(Value, V)**: 각 토큰이 실제로 들고 있는 내용.

Q, K, V는 어떻게 생길까요? 각 토큰의 임베딩 벡터에 학습된 행렬 세 개(Wq, Wk, Wv)를 곱해서
만듭니다. 같은 토큰에서 세 가지 다른 "얼굴"(질문용·색인용·내용용)을 뽑는 셈입니다.

```
토큰 벡터 x ──×Wq──> q (질문 얼굴)
            ──×Wk──> k (색인 얼굴)
            ──×Wv──> v (내용 얼굴)
```

이제 실제 계산을 작은 숫자로 따라가 봅시다. "먹었다"가 앞의 "나는", "밥을", "먹었다"를 보는
경우입니다.

**1단계: 점수 매기기(쿼리와 키의 내적).** 두 벡터를 곱해서 더하는 것이 내적이고, 두 벡터가
비슷한 방향일수록 큰 값이 나옵니다.

```
q(먹었다) · k(나는)   = 0.2   (별로 안 관련)
q(먹었다) · k(밥을)   = 2.0   (관련 큼)
q(먹었다) · k(먹었다) = 1.0   (자기 자신)
```

**2단계: softmax 로 비율 바꾸기.** 점수를 그냥 쓰지 않고, 다 더하면 1이 되는 비율로 바꿉니다.
이때 쓰는 함수가 softmax입니다. softmax는 각 점수에 exp(지수함수)를 씌운 뒤 전체로 나눕니다.
exp를 쓰는 이유는 큰 점수를 더 도드라지게(크게), 작은 점수를 더 작게 만들어 "고르는 느낌"을
주기 위해서입니다.

```
점수      [0.2,   2.0,   1.0]
exp 씌움  [1.22,  7.39,  2.72]      (e^0.2, e^2.0, e^1.0)
합 = 11.33
나누기    [0.108, 0.652, 0.240]     (다 더하면 1.0, 이게 "가중치")
```

**3단계: 밸류를 가중치만큼 섞기.** 위 비율대로 각 토큰의 밸류를 섞어 더하면 그게 "먹었다"가
어텐션으로 뽑아낸 결과입니다.

```
출력 = 0.108×v(나는) + 0.652×v(밥을) + 0.240×v(먹었다)
       (밥을 의 내용을 가장 많이 가져옴)
```

이걸 모든 토큰에 대해 한꺼번에 하면, "누가 누구를 얼마나 보는가"가 정사각형 표로 나옵니다.
행은 질문하는 토큰, 열은 보이는 토큰이고, 각 행을 softmax 해서 합이 1입니다.

```
            k:나는  k:밥을  k:먹었다
 q:나는      1.00    -       -          ← 행마다 softmax (합=1)
 q:밥을      0.30   0.70     -
 q:먹었다    0.11   0.65    0.24
```

수식 한 줄로 요약하면 다음과 같습니다. 위에서 말로 한 것을 기호로 옮긴 것뿐입니다.

```
어텐션(Q,K,V) = softmax( Q·Kᵀ / √d ) · V
                          │     │       └ 가중치로 밸류 섞기
                          │     └ √d 로 나눠 점수가 너무 커지는 것 방지(안정화)
                          └ 모든 쿼리와 모든 키의 점수표 (정사각형)
```

## 6. 인과 마스크: 미래를 컨닝하지 않기

글을 생성할 때는 "다음 단어 맞히기"가 목표입니다. 그러니 어떤 토큰이 점수를 매길 때 **자기보다
뒤(미래)에 있는 토큰은 보면 안 됩니다.** 아직 안 나온 답을 미리 보면 반칙이니까요. 그래서
점수표의 오른쪽 위(미래) 부분을 막습니다. 이걸 **인과 마스크(causal mask)**라고 합니다.

```
            나는  밥을  먹었다
 나는        ✓    ✗     ✗       ✗ = 막음(미래라 못 봄)
 밥을        ✓    ✓     ✗       ✓ = 봄(자기와 과거)
 먹었다      ✓    ✓     ✓
            └ 아래 삼각형만 살아남음 (계단 모양)
```

막는 방법은 간단합니다. 막을 칸의 점수를 아주 작은 값(사실상 마이너스 무한대)으로 두면,
softmax 후 그 칸의 가중치가 0이 됩니다. 그래서 미래 토큰은 전혀 안 섞입니다.

## 7. 트랜스포머 한 층 해부

2017년 "Attention Is All You Need" 논문이 RNN 없이 어텐션만으로 모델을 만들 수 있음을
보였고, 이 구조를 **트랜스포머(Transformer)**라고 부릅니다(출처: Vaswani et al., NeurIPS 2017,
arXiv:1706.03762). 지금 거의 모든 대형 언어 모델이 트랜스포머를 바탕으로 합니다.

한 문장 안에서 토큰들끼리 서로 보는 어텐션을 **셀프 어텐션(self-attention)**이라고 합니다.
트랜스포머는 이 셀프 어텐션을 핵심으로, 한 "층(레이어)"을 이렇게 구성합니다.

```
        입력 토큰 벡터들
            │
   ┌────────┴─────────┐
   │   ① 입력 정규화    │  (값의 크기를 고르게 맞춤)
   └────────┬─────────┘
            ▼
   ┌──────────────────┐
   │  ② 셀프 어텐션     │  (토큰들끼리 정보 주고받기, 5절)
   └────────┬─────────┘
            ▼
        ③ 잔차 더하기  ←──── 입력을 그대로 한 번 더 더함 (아래 설명)
            │
   ┌────────┴─────────┐
   │   ④ 정규화         │
   └────────┬─────────┘
            ▼
   ┌──────────────────┐
   │  ⑤ MLP (SwiGLU)   │  (각 토큰이 받은 정보를 혼자 한 번 더 가공)
   └────────┬─────────┘
            ▼
        ⑥ 잔차 더하기
            │
        출력 (다음 층의 입력)
```

각 부품을 조금 더 깊게 봅니다.

**잔차 더하기(residual).** 어텐션이나 MLP의 결과를 "원래 입력에 더하는" 방식입니다. 왜
이렇게 할까요? 층을 수십 개 쌓으면, 곱셈이 계속 이어져 정보가 사라지거나 학습이 안 되는
문제가 생깁니다. 입력을 그대로 더해 주면 "최소한 원래 정보는 보존되고, 층은 거기에 더할
보정값만 배우면" 되므로 깊게 쌓아도 안정적입니다. 고속도로에 비유해 "지름길(skip
connection)"이라고도 부릅니다.

```
   x ──────────────┐ (지름길: 원본 보존)
   │               │
   └─→ [어텐션] ──→ (+) ──→ 출력 = x + 어텐션(x)
                    보정값만 더함
```

**정규화(RMSNorm).** 벡터 안 숫자들의 크기를 고르게 맞추는 작업입니다. 어떤 숫자는 너무
크고 어떤 건 너무 작으면 학습이 흔들리므로, 벡터의 크기를 일정하게 다듬습니다. Qwen3 계열은
RMSNorm이라는 방식을 쓰는데, 벡터를 그 크기(제곱평균제곱근)로 나눠 정규화한 뒤 학습된
가중치를 곱합니다.

**MLP(SwiGLU).** 어텐션이 "다른 토큰에서 정보를 모아 오는" 일이라면, MLP는 "그 모아 온
정보를 각 토큰이 혼자 더 가공"하는 일입니다. 보통 차원을 크게 부풀렸다가(예: 2048 → 더 큰
중간 차원) 다시 줄이면서 비선형 변환을 합니다. SwiGLU는 그중 성능 좋은 방식으로, 두 갈래로
나눠 한쪽을 게이트(여닫이)로 써서 다른 쪽을 조절합니다.

```
   x → (게이트 갈래) ─┐
       (값 갈래)  ──── ⊗ → 줄이기 → 출력
                  곱해서 조절 (SwiGLU)
```

이 한 층을 수십 개 쌓아 깊은 모델을 만듭니다. 예를 들어 Qwen2.5-Coder-7B는 28층,
Qwen3-Coder-Next는 48층입니다.

## 8. 멀티헤드 어텐션(MHA)과 GQA

**멀티헤드(MHA).** 어텐션을 한 번만 하면 한 가지 관점만 봅니다. 그래서 어텐션을 여러 개의
"머리(head)"로 나눠, 머리마다 다른 관점으로 동시에 보게 합니다. 한 머리는 문법 관계, 다른
머리는 주제 관계, 또 다른 머리는 위치 관계를 보는 식입니다. 결과를 합치면 훨씬 풍부합니다.

```
          ┌→ [머리1: 문법 관계 본다]  ─┐
   입력 ──┼→ [머리2: 주제 관계 본다]  ─┼─→ 이어붙이기 → 출력
          └→ [머리3: 위치 관계 본다]  ─┘
   (각 머리는 자기 몫의 Q·K·V 를 따로 가짐)
```

**GQA(그룹 쿼리 어텐션).** 머리가 많으면 9절의 KV 캐시(키·밸류 저장)가 그만큼 커져서 메모리를
많이 먹습니다. 그래서 쿼리 머리는 많이 두되, 키·밸류 머리는 적게 두고 **여러 쿼리 머리가
키·밸류 한 묶음을 나눠 쓰게** 합니다. 메모리를 크게 아끼면서 성능은 거의 유지합니다.

```
   쿼리 머리 28개:  [Q1..Q7]   [Q8..Q14]   [Q15..Q21]   [Q22..Q28]
                       │           │            │             │
   키·밸류 머리 4개:   KV1         KV2          KV3           KV4
   (쿼리 7개가 KV 한 묶음을 공유 → KV 저장량이 1/7 로 줄어 메모리 절약)
   예: Qwen2.5-Coder-7B = 쿼리 28 / 키·밸류 4 / 7개씩 공유
```

Qwen3-Coder-Next의 풀 어텐션 층은 쿼리 머리 16개, 키·밸류 머리 2개(8개씩 공유), 머리 하나
크기 256입니다.

## 9. KV 캐시: 과거를 다시 계산하지 않기 (뒤에서 아주 중요)

언어 모델이 글을 한 토큰씩 만들 때, 새 토큰을 맞힐 때마다 앞 토큰 전체의 키·밸류를 처음부터
다시 계산하면 엄청난 낭비입니다. 앞 토큰들의 키·밸류는 한 번 정해지면 바뀌지 않으니까요.

그래서 한 번 계산한 과거 토큰들의 키·밸류를 저장해 두고 재사용합니다. 이 저장소가 **KV
캐시**입니다. 새 토큰이 나오면 그 토큰의 키·밸류만 새로 계산해서 캐시 **맨 뒤에 붙이고**,
어텐션은 캐시 전체를 봅니다.

```
 스텝1 ("나는")     KV캐시: [k1,v1]                        ← k1,v1 새로 계산
 스텝2 ("밥을")     KV캐시: [k1,v1][k2,v2]                 ← k2,v2 만 새로, 앞은 재사용
 스텝3 ("먹었다")   KV캐시: [k1,v1][k2,v2][k3,v3]          ← k3,v3 만 새로
                          └────── 뒤에 덧붙이기만(append) ──────┘
                          이미 저장된 과거 칸은 절대 안 고침
```

여기서 **아주 중요한 성질**을 기억하세요. KV 캐시는 **뒤에 덧붙이기만 하는(append-only)**
저장소입니다. 새 토큰이 오면 빈 칸 뒤에 붙일 뿐, 이미 있는 칸을 읽어서 고쳐 쓰지 않습니다.
NPU의 서빙 런타임도 이 "덧붙이기만 하는 KV 캐시"를 다루도록 만들어져 있습니다. 이 성질이
15절(Gated DeltaNet)과 18절에서 결정적인 걸림돌이 됩니다. 미리 못 박아 둡니다.

```
 KV 캐시 = 빈 칸에 차곡차곡 쌓기 (덧붙이기)        ← NPU 런타임이 아는 방식
 (나중에 나올 순환 상태 = 같은 칸을 읽고 고쳐 쓰기)  ← NPU 런타임이 모르는 방식
```

## 10. softmax 어텐션의 약점: 길이의 제곱(N²) 비용

어텐션은 강력하지만 비쌉니다. 5절의 점수표를 다시 보세요. 토큰이 N개면 "모든 토큰이 모든
토큰과" 점수를 매기므로 점수표가 N×N 칸입니다. 게다가 칸 하나를 채우려면 길이 d인 두 벡터의
내적(곱셈 d번)이 필요합니다. 그래서 계산량이 대략 N×N×d 입니다.

```
 N=4 점수표        N=8 점수표 (한 변이 2배 → 칸은 4배)
  ████              ████████
  ████              ████████
  ████              ████████
  ████              ████████
                    ████████
                    ████████
                    ████████
                    ████████
 칸 16개            칸 64개
```

길이가 2배가 되면 칸은 4배, 길이가 10배가 되면 칸은 100배가 됩니다. 이걸 "길이의 제곱(N²)
비용"이라고 부릅니다. 숫자로 느껴 봅시다(d=128 기준, 점수표 칸당 곱셈 d번).

```
 토큰 수 N    점수표 칸수 N²       대략 계산량 N²·d
   1,000        1,000,000          1.28억
  10,000      100,000,000          128억      (N 10배 → 100배)
 100,000   10,000,000,000          1.28조     (N 100배 → 10000배)
```

여기에 더해 9절의 KV 캐시도 토큰 수에 비례해 계속 커집니다. 그래서 수만 토큰짜리 긴 문서를
다루면 어텐션이 느려지고 메모리도 폭발합니다. "길이에 제곱으로 비싸다"는 이 약점을 줄이려는
시도가 다음의 선형 어텐션입니다.

## 11. 선형 어텐션: 결합법칙의 마법으로 비용을 길이에 "비례"하게

선형 어텐션의 목표는 N² 비용을 N 비용으로 낮추는 것입니다. 길이가 2배면 비용도 딱 2배만
되게 하려는 것입니다. 핵심 아이디어는 곱셈의 순서를 바꾸는 **결합법칙**입니다.

### 11-1. softmax 를 잠깐 치우면 보이는 것

softmax 어텐션의 출력은 (인과 마스크와 √d를 잠시 생략하면) 이렇게 씁니다.

```
 o_t = Σ_{i≤t}  (q_t · k_i)  v_i
                 └점수┘     └내용┘
       "지금까지의 각 토큰에 대해, (질문·색인 점수)만큼 내용을 섞어 더함"
```

`(q_t · k_i)`는 숫자 하나(점수)이고, `v_i`는 벡터입니다. 여기서 핵심 관찰은 `q_t`가 합 안의
모든 항에 공통으로 들어간다는 점입니다. 그래서 `q_t`를 합 밖으로 빼낼 수 있습니다(결합법칙).

```
 o_t = Σ_i (q_t · k_i) v_i  =  ( Σ_i  v_i k_iᵀ )  q_t
                                 └──────┬──────┘
                                 이걸 미리 한 행렬로 모아두면 = 상태 S_t
                                 (v_i k_iᵀ 는 두 벡터의 "외적", d×d 행렬)
```

즉 출력은 `o_t = S_t · q_t` 한 번의 곱으로 끝나고, `S_t`는 과거 정보를 모두 담은 고정 크기
(d×d) 행렬입니다. 토큰이 늘어도 `S`의 크기는 그대로입니다.

### 11-2. 왜 싼가 (곱셈 순서가 비용을 바꾼다)

같은 결과인데 계산 순서에 따라 비용이 완전히 다릅니다.

```
 softmax 방식:  먼저 (Q Kᵀ) 를 만든다     → N×N 점수표      → 비쌈  O(N²·d)
                     └ N×N ┘
 선형 방식:    먼저 (Σ v kᵀ)=S 를 만든다  → 작은 d×d 행렬   → 쌈    O(N·d²)
                     └ d×d ┘
```

N이 d보다 훨씬 클 때(긴 문서) 선형 방식이 압도적으로 쌉니다. 그리고 결정적으로, 길이 N에
대해 비용이 N에 **비례**(선형)합니다. 그래서 이름이 선형 어텐션입니다.

```
 N=1,000,  d=128 →  softmax 1.28억  vs  선형 1,640만   (약 8배 쌈)
 N=10,000, d=128 →  softmax 128억   vs  선형 1.64억    (약 78배 쌈)
```

### 11-3. RNN 의 부활: 상태를 한 토큰씩 갱신

`S_t = Σ_{i≤t} v_i k_iᵀ` 를 매번 처음부터 더할 필요는 없습니다. 직전 상태에 새 항만 더하면
됩니다. 그러면 RNN처럼 "상태 하나를 들고 한 토큰씩 갱신"하는 모양이 됩니다.

```
 S_0=0 ─(+ v1k1ᵀ)→ S_1 ─(+ v2k2ᵀ)→ S_2 ─ ... ─→ S_N
   고정 크기 d×d 행렬 하나를 계속 갱신 (RNN 의 기억 상자와 닮음)

 갱신:  S_t = S_{t-1} + v_t k_tᵀ      (새 정보를 더함)
 읽기:  o_t = S_t · q_t              (질문으로 꺼냄)
```

3절 RNN과 닮았지만 두 가지가 다릅니다. (1) 기억이 벡터가 아니라 행렬 S라 용량이 큽니다.
(2) 학습할 때는 11-1처럼 행렬곱으로 한꺼번에(병렬) 계산할 수 있습니다. 즉 "추론은 RNN처럼
싸게, 학습은 트랜스포머처럼 병렬로"를 노립니다. 다만 이 단순 버전에는 큰 약점이 있는데,
그게 다음 절입니다.

## 12. 단순 누적의 한계: 메모리 충돌

11절의 갱신은 **더하기뿐**입니다. 새 정보를 계속 더하기만 하고 옛 정보를 지울 방법이 없습니다.
문제는 글이 길어질 때입니다. 서로 다른 토큰의 키가 비슷한 방향이면, 그 정보들이 한 행렬 S
안에서 겹쳐 뭉개집니다.

```
 단순 누적:  S = v1k1ᵀ + v2k2ᵀ + v3k3ᵀ + ...   (지우기 없음)

 키가 서로 비슷하면(충돌):       꺼낼 때
   ▓ (v1 자리)                  q 로 읽으면 v1·v2·v3 가
   ▒▓ (v2 가 겹침)              섞여 나와서 흐릿함
   ▒▒▓ (v3 가 또 겹침)          "그래서 자전거 누구 줬더라?" → 흐림
```

비유하면, 칠판 한 장에 새 글씨를 지우지 않고 계속 덧쓰는 것과 같습니다. 처음엔 또렷하지만
나중엔 글씨가 겹쳐 못 읽게 됩니다. 좋은 메모리라면 새 정보를 넣을 자리를 만들려고 덜
중요한 옛 정보를 지울 줄 알아야 합니다. 여기서 delta rule이 나옵니다.

---

## 13. delta rule: 읽고-고치고-쓰기

delta rule(델타 규칙)의 핵심은 "쓰기 전에 한 번 읽어 보고, 틀린 만큼만 고치기"입니다.
"델타"는 차이라는 뜻입니다. 칠판에 덧쓰기만 하지 말고, 그 자리를 먼저 읽어서 지우고 새로
쓰자는 것입니다.

```
 새 토큰의 키 k 로 ...
   ① 읽기:    v_old = S · k          (이 키에 대해 S 가 지금 기억하는 값)
   ② 차이:    Δ = (v_new − v_old)·β   (정답과 옛값의 차이, β=쓰기 세기 0~1)
   ③ 고쳐쓰기: S ← S − v_old·kᵀ + (v_old+Δ)·kᵀ
              = S + (Δ)·kᵀ            (옛값 자리를 지우고 새값으로 덮는 효과)
```

### 13-1. 왜 이게 "옛 메모리를 정리하는" 학습 한 스텝인가

delta rule은 사실 아주 유명한 학습 규칙(Widrow-Hoff, 1960)이고, **온라인 경사하강 한 스텝**으로
유도됩니다. "S가 키 k를 넣으면 정답 v가 나오게 하라"는 목표를 손실로 적으면:

```
 손실  L(S) = ½ ‖ S·k − v ‖²        (S로 예측한 값과 정답의 차이의 제곱)
 기울기 ∇L  = ( S·k − v ) kᵀ         (이 방향으로 가면 손실이 커짐)
 갱신       S ← S − β·∇L = S − β(S·k − v)kᵀ
           = S − β(v_old − v)kᵀ      (위 ②③ 과 똑같음)
```

즉 메모리 행렬 S는 "키→값 연관"을 매 토큰마다 한 스텝씩 학습하는 "빠른 가중치(fast
weight)"입니다. 이 관점이 15절에서 "게이트 = weight decay"라는 통찰로 이어집니다.

### 13-2. 작은 숫자 예제

이해를 굳히려고 가장 단순한 경우(키도 값도 숫자 하나, d=1)로 봅시다. S=2를 기억하고 있는데,
이 키에 대해 정답이 v=5라고 합시다.

```
 S_old = 2,  k = 1,  v = 5
 ① v_old = S·k = 2          (옛값)
 ② Δ = β(v − v_old) = β(5−2) = 3β
 ③ S_new = S + Δ·k = 2 + 3β

   β = 1 이면  S_new = 5   (정답으로 완전히 덮어씀)
   β = 0 이면  S_new = 2   (안 건드림)
   β = 0.5 이면 S_new = 3.5 (절반만 옮김)
```

β가 "얼마나 세게 덮어쓸지"를 정합니다. 단순 누적(12절)은 항상 더하기만 했지만, delta rule은
먼저 읽어서 그 자리를 정리하고 쓰므로 메모리가 또렷하게 유지됩니다. 이 방식을 쓰는 모델이
**DeltaNet**입니다(출처: Yang et al., NeurIPS 2024, arXiv:2406.06484).

## 14. DeltaNet: 행렬값 RNN과 청크 병렬

### 14-1. 전이행렬로 다시 보기

13절의 갱신식 `S ← S − β(S·k − v)kᵀ` 를 S에 대해 정리하면 이렇게 묶입니다.

```
 S_t = S_{t-1}·( I − β k k ᵀ ) + β v k ᵀ
                └─── 전이행렬 ───┘  └ 새 정보 ┘
```

`( I − β k kᵀ )` 가 전이행렬입니다. 단순 선형 어텐션(11절)은 전이행렬이 그냥 I(항등, 아무것도
안 함)였는데, DeltaNet은 `I − β k kᵀ`(Householder라는 특별한 모양)입니다. 그래서 DeltaNet은
"전이행렬이 항등이 아닌, 행렬을 상태로 쓰는 RNN"입니다. 이 한 끗 차이가 메모리 정리 능력을
줍니다.

### 14-2. 청크 병렬: 추론은 한 토큰씩, 학습은 덩어리로

순환식(한 토큰씩)은 추론(특히 한 토큰씩 만드는 decode)에는 좋지만, 학습 때는 줄 세워 계산해야
해서 느립니다. 반대로 한 번에 다 펼치면 빠르지만 N² 비용이 돌아옵니다. 그래서 DeltaNet은
중간을 택합니다. 문장을 길이 C(보통 64나 128)짜리 **청크(덩어리)**로 쪼개서, "청크 사이는
순환(상태 S를 넘김), 청크 안은 병렬(행렬곱)"로 처리합니다.

```
 [청크1: 64토큰]      [청크2: 64토큰]      [청크3: 64토큰]
   내부=한꺼번에         내부=한꺼번에         내부=한꺼번에
   행렬곱(병렬)          행렬곱(병렬)          행렬곱(병렬)
        │                   │                    │
   S_0 ─┴── carry ──→ S_1 ──┴── carry ──→ S_2 ──┴→ ...
        청크 사이만 상태를 순서대로 넘김
```

청크 하나의 출력은 두 부분의 합입니다. (1) 직전 청크까지의 상태 S에서 읽은 부분(청크 간
기여), (2) 청크 안 토큰들끼리의 보통 어텐션 부분(청크 내 기여).

### 14-3. 왜 청크 안 계산에 삼각역행렬이 필요한가 (실전에서 중요)

DeltaNet의 전이행렬은 항등이 아니라서, 청크 안에서 이 행렬들의 누적곱이 등장합니다. 이걸
매 토큰 펼치면 비싸지므로, 논문은 이를 압축하는 영리한 변환(UT/WY 변환)을 씁니다. 그
과정에서 **하삼각 행렬의 역행렬**을 한 번 구해야 합니다. 실제 HuggingFace 구현에서도 청크
크기만큼 도는 작은 루프로 이 삼각역행렬을 풉니다.

```
 청크 안 누적곱  ∏(I − β k kᵀ)  →  T = (I − strictLower)⁻¹  (삼각역행렬)
                                    이걸로 W, U 를 구하면 나머지가 전부 행렬곱이 됨
```

이 삼각역행렬·cumsum(누적합) 계산은 상태 S와 무관해서 host(CPU)가 미리 계산해 둘 수
있습니다. 이 점이 [README_qwen3_coder_next.md](README_qwen3_coder_next.md)에서 "청크 prefill은
host 사전계산이 필요하다"는 제약의 뿌리입니다. 지금은 "DeltaNet 청크 계산엔 삼각역행렬이
꼭 필요하고, 그건 미리 계산해 둘 수 있다" 정도만 기억하면 됩니다.

## 15. Gated DeltaNet: 망각 게이트를 더하다

### 15-1. 두 종류의 메모리 관리, 그리고 합치기

DeltaNet은 "특정 연관을 콕 집어 정밀 수정"은 잘합니다. 그런데 화제가 확 바뀌어 메모리 전체를
빠르게 비워야 할 때는 약합니다(한 번에 하나씩만 고치니까). 반대로 Mamba2 같은 방식은 매
토큰마다 상태 전체에 0~1 사이 **망각 값 α**를 곱해 조금씩 흐리게 만드는 "망각 스위치"가 있어
빠른 망각은 잘하지만, 특정 연관만 정밀하게 고치진 못합니다. 셋을 나란히 비교하면:

```
 Mamba2:         S_t = α·S_{t-1} + v k ᵀ              (전체 균일 감쇠. 정밀수정 없음)
 DeltaNet:       S_t = S_{t-1}(I − β k k ᵀ) + β v k ᵀ  (정밀수정. 망각 없음)
 Gated DeltaNet: S_t = α·S_{t-1}(I − β k k ᵀ) + β v k ᵀ (둘 다!)
                       └α: 빠른 망각┘ └β: 정밀수정┘
```

**Gated DeltaNet**은 망각 게이트 α와 delta rule β를 한 식에 합칩니다(출처: Yang, Kautz,
Hatamizadeh, ICLR 2025, arXiv:2412.06464). α가 1에 가까우면 안 잊고(순수 DeltaNet), α가
작으면 많이 잊습니다(망각 위주). β가 0이면 메모리를 안 건드립니다(순수 Mamba2). 즉 두 극단을
모두 포함하는 일반형입니다.

### 15-2. "게이트 = 적응적 weight decay" 라는 통찰

13-1절에서 delta rule이 "온라인 경사하강 한 스텝"이라고 했습니다. 거기에 α를 곱하는 것은
딥러닝에서 흔히 쓰는 **weight decay**(가중치를 매 스텝 살짝 줄여 과적합·발산을 막는 기법)를
메모리 행렬에 적용하는 것과 같습니다. 논문은 여러 선형 RNN을 "온라인 학습 목적함수"로
통일해 보여 줍니다.

```
 방법             메모리 유지 항            정밀 수정 항
 Linear Attn      ‖S_t − S_{t-1}‖²          (없음)
 Mamba2           ‖S_t − α·S_{t-1}‖²        (없음)         ← α로 유지 항을 느슨하게(잊기)
 DeltaNet         ‖S_t − S_{t-1}‖²          delta rule     ← 정밀 수정만
 Gated DeltaNet   ‖S_t − α·S_{t-1}‖²        delta rule     ← 잊기 + 정밀 수정
```

`‖S_t − S_{t-1}‖²`는 "이전 상태에서 너무 멀어지지 마라"는 메모리 유지 규칙입니다. 메모리가
정보로 가득 차면 이 유지 규칙이 오히려 방해가 됩니다(겹쳐 저장돼 못 꺼냄). α를 곱해 유지
규칙을 느슨하게 풀어 주면, 필요할 때 옛 상태에서 의도적으로 벗어나 선택적으로 잊을 수
있습니다.

실제 효과는 논문의 긴 글 속 정보 찾기(S-NIAH) 평균 점수에서 분명합니다. 어려운 S-NIAH
항목들의 평균에서 DeltaNet 14.4, Mamba2 17.0인데 Gated DeltaNet은 29.6으로 둘 다를 크게
앞섭니다(출처: Gated DeltaNet 논문 표).

### 15-3. Qwen3-Next 구현에서의 게이트

Qwen3-Next는 망각 값 α를 직접 저장하지 않고, 로그값 g를 거쳐 만듭니다. β는 시그모이드입니다.

```
 β = sigmoid(b)                              (0~1, 쓰기 세기)
 g = −exp(A_log)·softplus(a + dt_bias)       (항상 0 이하)
 α = exp(g)                                  (0~1, g가 0 이하라 α도 1 이하 → 감쇠)
```

순환 한 스텝을 풀어 쓰면 정확히 15-1의 식이 됩니다. 그림으로:

```
 한 토큰 처리 (decode 한 스텝)

   S(옛 상태) ──×α──→ (감쇠된 S)
                        │ k 로 옛값 읽기:  kv = (감쇠S)·k
                        │ 차이:           Δ = (v − kv)·β
                        ▼
   S(새 상태) = 감쇠S + k⊗Δ      (외적으로 새 정보 씀)
   출력      = q·S(새 상태)
```

### 15-4. 이게 NPU 서빙을 막는 바로 그 성질입니다

여기서 9절의 약속을 지킬 차례입니다. Gated DeltaNet의 상태 S는 9절의 KV 캐시와 **메모리
관리 방식이 근본적으로 다릅니다.**

```
 KV 캐시(풀 어텐션):  토큰이 늘면 뒤에 [새 칸] 덧붙이기만 (append-only)
                      [k1][k2][k3][k4]...  ← 칸이 늘어남, 옛 칸은 그대로

 순환 상태(DeltaNet): 크기 고정 d×d 행렬을 매 토큰 읽고 고쳐 다시 쓰기 (read-modify-write)
                      [ S ] ← α 곱하고 Δ 더해서 같은 자리에 덮어씀
                      칸이 안 늘어남, 대신 매번 통째로 갱신
```

NPU의 표준 서빙 런타임은 "뒤에 덧붙이기만 하는 KV 캐시"만 다룰 줄 압니다. "같은 자리를 읽고
고쳐 쓰는" 순환 상태를 담을 자리가 없습니다. 그래서 Qwen3-Coder-Next를 표준 방식으로 NPU에
서빙하기가 어렵습니다. 자세한 이야기와 우리의 우회법은 18절과
[README_qwen3_coder_next.md](README_qwen3_coder_next.md)에 있습니다.

## 16. Gated Attention: 어텐션 "출력"에 거는 게이트

지금까지의 게이트(망각 게이트 α)는 상태 메모리에 거는 것이었습니다. **Gated Attention**은
그것과 다른 곳에 겁니다. 보통의 softmax 어텐션(5절) 결과가 나오면, 그 옆에서 따로 계산한
0~1 사이 게이트 값을 원소별로 한 번 더 곱합니다.

```
 입력 → [보통 어텐션 SDPA] ─→ (어텐션 결과) ──⊗── → o_proj → 최종 출력
                                              │
                            σ(게이트) ────────┘  (0~1, 쿼리에서 만듦)
```

게이트가 쿼리에서 나오므로 "지금 질문에 따라" 어떤 정보를 통과시키고 어떤 건 줄일지
조절합니다. 이 작은 추가가 (1) 모델 표현력을 높이고(어텐션은 본질적으로 가중평균이라 밋밋한데
비선형성을 더함), (2) 학습을 안정시키고, (3) 첫 토큰 같은 곳에 어텐션이 쏠리는 현상(attention
sink)을 줄인다고 알려져 있습니다(출처: Qiu et al., NeurIPS 2025, arXiv:2505.06708).

Qwen3-Next의 풀 어텐션 층이 이 방식입니다. 구현상으로는 q_proj가 보통의 2배 크기를 내놓고,
절반을 쿼리로, 절반을 게이트로 씁니다.

```
 q_proj 출력 (2배 크기) ──반으로 나눔──> [쿼리 절반]  → 어텐션
                                       [게이트 절반] → σ() → 어텐션 결과에 곱
```

참고로 Gated DeltaNet 층에도 비슷한 출력 게이트가 따로 있습니다(SiLU로 게이팅된 정규화).
그래서 Qwen3-Next에는 이름이 다 "gated"인 게이트가 세 군데 있습니다. 헷갈리지 않게 위치를
정리하면: (a) DeltaNet 상태에 거는 망각 게이트 α, (b) DeltaNet 출력에 거는 SiLU 게이트,
(c) 풀 어텐션 출력에 거는 시그모이드 게이트(이게 Gated Attention).

## 17. 다 합치면: Qwen3-Coder-Next 해부

이제 쌓아 온 부품으로 실제 모델을 조립해 봅니다. Qwen3-Coder-Next-FP8은 약 80B(800억)
파라미터, 48개 층입니다. 핵심은 "싼 선형 어텐션을 많이, 정확한 풀 어텐션을 가끔" 섞는
하이브리드라는 점입니다.

```
 48개 층의 배치 (4개마다 1개가 풀 어텐션)

 층 0   Gated DeltaNet  (선형, 쌈)
 층 1   Gated DeltaNet
 층 2   Gated DeltaNet
 층 3   풀 어텐션 (Gated Attention)   ← 정확한 전역 참조
 층 4   Gated DeltaNet
 층 5   Gated DeltaNet
 층 6   Gated DeltaNet
 층 7   풀 어텐션 (Gated Attention)
 ...                                  (이 패턴 12번 반복)
 층 47  풀 어텐션 (Gated Attention)

 합계:  36개 Gated DeltaNet + 12개 풀 어텐션
 그리고 모든 층에 MoE 가 붙음 (아래)
```

왜 섞을까요? 순수 선형 어텐션은 빠르고 긴 글에 싸지만 정밀한 검색이 약하고, 풀 어텐션은
정확하지만 비쌉니다. 그래서 다수의 Gated DeltaNet이 비용을 낮추고, 주기적으로 끼운 풀
어텐션이 "정확한 전역 참조"를 책임집니다.

각 층의 머리 구성(7~8절 용어로):
- Gated DeltaNet 층: 키 머리 16개, 밸류 머리 32개(밸류가 2배), 머리 크기 128, 짧은
  conv(커널 4, 직전 몇 토큰을 살짝 섞는 지역 패턴 잡기).
- 풀 어텐션 층: 쿼리 머리 16개, 키·밸류 머리 2개(GQA, 8개씩 공유), 머리 크기 256, 부분
  RoPE(머리의 25%에만 위치 정보), 출력 게이트(Gated Attention).

### 17-1. MoE: 512명의 전문가 중 10명 골라 쓰기

모든 층에는 7절의 MLP 대신 **MoE(Mixture of Experts, 전문가 혼합)**가 붙습니다. MLP를
하나만 두지 않고 작은 MLP("전문가")를 512명 두고, 토큰마다 그중 가장 잘 맞는 10명만 골라
쓰고, 항상 쓰는 공유 전문가 1명을 더합니다.

```
 토큰 → [라우터] → 512명 전문가 점수 매김 → 상위 10명 선택
                                              │
            ┌── 전문가 #37  (가중치 0.4) ──┐  │
            ├── 전문가 #128 (가중치 0.3) ──┤  │ + 공유 전문가 1명(항상)
            ├── ... (총 10명) ───────────┤  ▼
            └────────────────────────────┴→ 가중합 → 출력
```

이래서 전체 파라미터는 80B로 크지만, 토큰 하나가 실제로 쓰는 부분(활성 파라미터)은 약
3B로 작습니다. 큰 지식은 512명에 나눠 담되, 매번 일하는 사람은 10여 명이라 빠릅니다.

### 17-2. 한 층을 통과하는 토큰의 여정 (전체 그림)

```
 토큰 벡터들
   │
   ├─[입력 정규화]→[토큰 믹서]→(+잔차)     토큰 믹서 = 층 종류에 따라
   │                                        DeltaNet(36층) 또는 풀 어텐션(12층)
   │
   └─[정규화]→[MoE: 라우터+전문가10+공유]→(+잔차)
   │
   ▼
 다음 층으로 (48층 반복) → 최종 정규화 → lm_head → 다음 토큰 확률
```

## 18. 왜 NPU 표준 서빙이 어려운가 (개념의 결론)

지금까지의 모든 내용이 한 지점으로 모입니다. 한 모델 안에 메모리 관리 방식이 다른 두 종류의
층이 섞여 있다는 것입니다.

```
 풀 어텐션 층(12개):  KV 캐시 = 토큰마다 [새 칸] 덧붙이기 (append-only)
                      → NPU 표준 런타임이 다룰 줄 아는 방식

 Gated DeltaNet 층(36개): 순환 상태 = 고정 크기 행렬을 읽고 고쳐 쓰기 (read-modify-write)
                      → NPU 표준 런타임에 담을 자리가 없음
```

NPU의 표준 서빙 런타임은 softmax 어텐션의 "덧붙이기만 하는 KV 캐시"를 위해 설계됐습니다.
그래서 36개 DeltaNet 층이 요구하는 "같은 자리를 읽고 고쳐 쓰는 순환 상태"를 담을 수 없습니다.
이것이 Qwen3-Coder-Next를 표준 `furiosa-llm serve`로 그대로 돌리지 못하는 근본 이유입니다.

우리가 이 벽을 어떻게 우회했는지(상태를 host가 들고 도는 추론 루프, 계산을 NPU 커널로 직접
작성하고 쪼개 컴파일하기, furiosa-llm serve 서버를 우리 엔진으로 구동하기)는 다음 문서에
실전으로 정리돼 있습니다.

- furiosa-llm CLI(build/serve) 개념: [README_furiosa_llm_cli_explained.md](README_furiosa_llm_cli_explained.md)
- Qwen3-Coder-Next 실전(우리 해법·명령): [README_qwen3_coder_next.md](README_qwen3_coder_next.md)
