# 보수화 감사 리포트 — register-aware 토큰 압축 (2026-07-01)

이 문서는 논문 자료를 **보수적·객관적**으로 만들기 위해, 5개 적대적 감사 에이전트(주장↔실측 대조·모순·과판단·방법론·신규성)가 실제 파일을 읽고 찾은 것을 종합한 것입니다. 결론부터: **핵심 수치는 정직하고 재현되나(거짓 없음), 프레이밍·정밀도·일반화가 데이터를 넘어섭니다.** 아래 "반드시 수정"을 반영해야 제출 가능합니다.

## A. 견고한 사실 (자신 있게 써도 됨)
- **모든 표 셀이 원자료와 정확히 일치**하고 산술(+8.07%, 71.98, 63.91, "4.4% below full")이 맞음. 조작·과장된 숫자 없음.
- **DINOv2-ViT-B/14(register 4개), 단일 seed, kNN k=20**에서: register 보호가 ToMe식 병합 대비 **+1.01→+8.07(37%→92% 축소)**. 이 +8%는 어떤 노이즈 바닥(±0.05~0.4%)보다 **훨씬 큼** → 신호 자체는 진짜.
- **동일 개수 keep-prior ablation**: random/energy/highnorm 모두 ~64% vs register 71.98%(91% 축소) — 큰 격차.
- **좁은 신규성은 방어 가능**: RegCache(양자화, 토큰 유지)·FNA(어텐션 근사, 토큰 유지)·CubistMerge(공간/최대크기, register 무관, >90% 없음)·PiToMe(에너지, register 무관) 모두 **register를 토큰 *축소*의 명시적 keep-prior로 쓰지 않음**.
- 원고(main.md)는 NPU/dense/retrieval을 **[TODO]/pending으로 정직 표기**(라이브 과장 없음). 과거 "NPU=GPU 정확도" 과판단은 현 원고엔 없음(reg4는 NPU서 cosine 1.0).

## B. 반드시 수정 (과장·모순 — 보수적 재서술)

1. **범위 과일반화(major, 다수 지적).** 제목 "Foundation Vision Encoders"+"DINOv2/CLIP/SigLIP"인데 유효 양성은 **DINOv2-reg 단 1개**(단일 seed·단일 지표 kNN). CLIP은 projection 누락으로 1.6%≈바닥(무효), SigLIP 미실행. → **제목·초록을 "register 장착 인코더(DINOv2-ViT-B/14-reg4)"로 축소**, "단일 체크포인트·단일 지표(kNN)·단일 seed" 명시, CLIP/SigLIP는 동기부여/향후과제로 격하.
2. **high-norm 일반화 모순(major).** 초록/서론/방법이 "high-norm artifact 토큰이 전역정보를 담고 병합이 파괴 → top-k high-norm 보호로 일반화"를 **메커니즘으로** 내세우나, 자체 ablation은 정반대(highnorm이 reg·plain 모두서 이득 ~0). → **초록/서론에도 방법 본문의 hedge를 반영**: high-norm 보호는 "검증 안 된 자연 확장, 실측 모델서 ToMe 대비 이득 없음". 시연된 이득은 **명시적 register 토큰에 한정**.
3. **효율 논문인데 speedup 증거 0 + NPU는 오히려 느림(major).** 핵심 동기가 가속인데 실측 NPU는 0.87~0.9x(느려짐, 74% 축소까지). 게다가 npu_latency는 실제 병합(argsort/scatter)이 아니라 **정적 슬라이스 대리물**을 잼. → **"speed up"·"negligible cost" 삭제**(근거 확보 전). 효율은 **토큰수/FLOP 감소**(진짜 낮음)로 제시, NPU는 "이 칩·이 구간서 속도 이득 없음"을 정직한 한계로. npu_latency.py 해석 문구도 데이터에 맞게 수정.
4. **베이스라인 "ToMe"가 정식 ToMe 아님(major).** proportional(log-size) attention 미구현·병합 위치(블록 후)·유사도 지표(정규화 feature)가 다름. → **"size-weighted bipartite merging (ToMe-style, proportional attention 없음)"으로 표기**(양 팔 공통). 또는 정식 ToMe 재구현/공식 repo head-to-head.
5. **ablation keep-prior가 입력단 1회 고정 선택(major).** highnorm/energy를 pos-embed 직후(레이어0)에 한 번 골라 12블록 고정. 아티팩트는 중간층(우리 자신 측정=block9)서 발생, PiToMe 에너지는 층별 재채점. → **"정적 입력단 highnorm/energy prior는 register 보호에 못 미침"으로 약화 서술**, 동적 재선택 변형은 미검증임을 명시(추가실험 대상).
6. **kNN 비표준(major).** val을 질의·갤러리 양쪽으로(leave-one-out), k=20 단일. 표준 DINOv2는 train 갤러리+linear-probe; 토큰축소 문헌은 모델 지도헤드/linear-probe top-1. full kNN 76.35도 img224(비-native 518)라 낮음. → **linear-probe top-1 추가**, 동작점(저해상도·val-갤러리) 명시.
7. **단일 seed·오차막대 없음인데 통계 언어(major).** scatter_add 비결정. "statistically indistinguishable"·2자리 "monotonic"은 근거 부족(일부 격차가 ±0.05 노이즈 내: energy +0.14, highnorm +0.08). → **≥3 seed 평균±표준편차**; "statistically indistinguishable"→"ToMe 대비 ≤0.X%(register 이득의 1/수십)"; 미세구조 주장 자제. **+8% 헤드라인은 확고히** 써도 됨.
8. **음성대조군이 순환적(major).** register 없으면 Ours≡ToMe(구성상 동일)라 Δ≈0은 자명 → **노이즈 바닥·하네스버그 배제**만 성립, "원인=register 확증"은 아님. 게다가 plain은 병합에 이미 강건(ToMe -4.2 vs reg -12.4)이라 confound. → **대조군=노이즈 바닥 sanity로 서술**, 인과는 **표3 ablation**에 귀속. ±0.05 "GPU 비결정"은 코드상 재현 안 됨(같은 캐시키→Δ≡0)이니 "구성상 Δ≡0" 또는 독립재실행으로 정정.
9. **압축률 92% vs 91% 불일치 + 동일예산 아님(minor).** 같은 동작점이 표1 92%·표3 91.2%·대조 93%. r=20서 ours 23토큰 vs tome 21토큰(=ours가 2토큰 더 남김). → **실현 압축률(~91%)로 통일**, 각 팔의 **실제 최종 토큰수(=FLOP) 표기**, 주장은 "동일개수 keep-prior 대비 +7.9"로.
10. **"PiToMe-style energy"=프록시(major).** 실제 PiToMe(층별 스펙트럴 에너지+병합)가 아니라 평균코사인 keep-prior. → **"beats PiToMe" 함의 전면 삭제**; "PiToMe의 보호신호 취지의 energy keep-prior(방법 자체 아님)"로 명명; 실제 PiToMe repo head-to-head는 추가실험.
11. **"collapse" 과장 + 병합증거 부재(minor).** 63.9%(랜덤 훨씬 위)로 떨어진 걸 "collapse"라 함; ToMe가 register를 실제 병합한다는 직접 증거 없음(간접 추론). → **"큰 정확도 하락(63.9%로)"**, "register가 병합돼 사라지는 것과 일치"; 가능하면 register-병합빈도 직접 측정.
12. **문서 과서술(minor).** dense README가 미실행 mIoU 결론을 현재형 단언, 핵심정리 §5가 DINOv3/가지치기로 일반화. → 가설(pending)로 서술, 0.71-vs-0.49는 "예비 cosine 프록시(작은 N)"로 명시.
