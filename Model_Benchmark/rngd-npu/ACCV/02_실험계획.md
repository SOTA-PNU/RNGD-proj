# 02. 실험 계획 — 무엇을, 어떤 순서로, 어떻게

이 문서는 논문의 실험을 단계별로 무엇을·왜·어떻게(실제 명령어까지) 하는지 정리한 실행 계획서입니다. 주제 설명은 [01_논문주제.md](01_논문주제.md), 쓰는 코드의 의미는 [03_사용하는_코드와_경로.md](03_사용하는_코드와_경로.md)에 있습니다.

## 0. 큰 그림 — E0가 모든 것을 가른다

실험을 E0~E4 단계로 굴립니다. **E0(첫 VL forward)가 성립 여부의 관문**입니다. 통과하면 진단(E2)→복구(E3)까지, 막히면 host-loop 폴백으로 **진단-only** 논문이라도 확보합니다.

| 단계 | 하는 일 | 통과 기준 | 비고 |
|---|---|---|---|
| **E0** (★게이트) | Qwen3-VL의 첫 on-NPU forward를 띄운다 | 이미지+질문 1쌍에 칩에서 멀쩡한 답이 나옴 | 미검증·최대 리스크 |
| **E1** 붕괴 표면화 | bf16 기준 vs FP8 vs MXFP4 시각 정확도 비교 | 저정밀에서 시각 정확도 하락이 관측됨 | FP8가 보호하면 MXFP4로 유도 |
| **E2** 국소화(진단) | 비전 타워 / 융합부 / 디코더 중 어디가 먼저 깨지나 | "비전 타워가 먼저"를 정확도·outlier로 입증 | 논문 헤드라인 |
| **E3** 복구 | per-channel·per-block 가중치접기 스케일로 되살림 | 시각 정확도 회복 곡선(정확도 vs 정밀도 예산) | 새 vISA 커널 불요 |
| **E4** 효율(보조축) | 비주얼-토큰 예산 vs throughput·dp/pp 스케일 | Pareto 곡선 | 이미 도는 모델로 **오늘** 가능 |

평가 벤치마크는 **시각 중심**(DocVQA·ChartQA·TextVQA·OCR·grounding) — perplexity·tok/s를 헤드라인에 쓰지 않습니다(ACCV 스코프).

## 1. 환경 준비

```bash
source ~/furiosa/bin/activate            # 퓨리오사 SDK 2026.2.0
furiosa-smi status                       # 카드 확인 — 현재 npu0~3 4장 전부 유휴
A=~/RNGD-proj/Model_Benchmark/rngd-npu/artifacts   # 빌드 아티팩트 둘 곳
```
재사용 자산(이미 검증됨):
- **LLM 서빙 스파인:** `chat/serve_models.sh` 가 `furiosa-llm serve <아티팩트> --devices <PE> --port <p>` 로 tp8 모델을 띄움(Qwen3-32B·Coder-30B-A3B 등). VL도 같은 경로를 미러링.
- **FP8 MoE 부활:** masquerade(artifact.json model_type 위장)로 게이트 통과 — Qwen3-Coder-30B-A3B-FP8이 이 방식으로 4장 dp 1036 tok/s.
- **host-loop 폴백:** `qwen3-next-proj/qcn/serve_q25.py`(furiosa.torch 계산 + FastAPI) — 빌드가 막혀도 칩에서 forward를 돌리는 우회로.
- **SDK의 VL 구현:** `furiosa/models/language/architecture/qwen3_vl/`(modeling.py·exec_module.py) — 벤더가 구현한 유일 비전 모델.

## 2. 단계별 실행 방법

### E0 — 첫 VL forward (★제일 먼저)
- **무엇:** Qwen3-VL을 RNGD에 올려 이미지+질문 1쌍에 칩에서 답이 나오는지 확인.
- **모델:** `Qwen3-VL-30B-A3B-Instruct-FP8`(이미 도는 Coder-30B-A3B-FP8과 같은 MoE·A3B·FP8 봉투 → 빌드/서빙 성공 확률 최고). 다운로드 중.
- **블로커와 우회:** qwen3_vl **버킷 프리셋이 없어** 버킷을 비우면 `resolver.py:92`가 raise합니다. → `furiosa-llm build`의 **`-pb`(prefill)·`-db`(decode) 로 버킷을 직접 지정**해 우회합니다. 동적 이미지 해상도는 벤더 ~1년 로드맵 공백이라 **이미지 해상도를 고정(static HxW grid_thw)** 해 빌드합니다.
```bash
# (a) 정공법: 수동 버킷으로 빌드 → serve
furiosa-llm build $CKPT --name qwen3-vl-30b-a3b-fp8 -tp 8 \
   -pb 1,4096 -db 1,4096 --max-model-len 32768           # 버킷은 실측하며 조정
furiosa-llm serve $A/qwen3-vl-30b-a3b-fp8 --devices "npu:0:0-7" --port 8010
# 게이트 통과 = 이미지+질문에 캡션/VQA 답이 칩에서 나옴(model_type 위장이 필요하면 masquerade 적용)
```
- **폴백(같은 48시간 안):** 빌드가 막히면 **host-loop**(`serve_q25.py` 방식, furiosa.torch + FastAPI)로 VL forward를 돌립니다(느리지만 실제 칩). 동시에 **비전 타워만** furiosa.torch로 컴파일(Backup A)해 진단 기반을 확보합니다.
- **게이트 판정:** 칩에서 멀쩡한 답이 나오면 E1로. 안 나오면 host-loop·비전타워-only로 **진단-only** 경로 전환(어느 쪽이든 논문 최소본 확보).

### E1 — 붕괴 표면화
- **무엇:** 같은 이미지+질문 세트에서 **bf16(기준) vs 칩 FP8 vs MXFP4** 시각 정확도를 비교.
- **주의:** SDK FP8가 prequant per-block 스케일로 비전 타워를 LLM처럼 보호하면 붕괴가 안 보입니다. 그땐 **MXFP4 등 더 거친 경로**로 붕괴를 끌어냅니다. 동시에 우리 레포의 미해결 모순("conv/mm ~0.23% 일정" vs "100% 붕괴")을 **이 트랜스포머에서 실제 포맷·주범(라운딩 vs 클립)을 측정**해 해소합니다 — 그래야 "붕괴"라는 단어를 쓸 수 있습니다.

### E2 — 국소화 (진단 헤드라인)
- **무엇:** 비전 타워 / 멀티모달 융합부 / 언어 디코더의 **컴포넌트별 activation·outlier 통계**와 정확도 기여를 재서, **비전 타워가 먼저 무너짐**을 보입니다.
- **어떻게:** 컴포넌트별로 bf16↔저정밀을 바꿔 끼우며(가능한 범위) 정확도 변화를 측정(forward hook). 시각 벤치마크로 평가.

### E3 — 복구
- **무엇:** 망가지는 컴포넌트(주로 비전 타워)의 **채널·블록별 스케일을 인접 affine에 접어** 정밀계산 결과는 불변, 저정밀에서만 유리하게.
- **검증:** 접은 뒤 정밀계산 결과 불변을 assert, 시각 정확도 vs 정밀도 예산 곡선. 새 저수준 커널은 필요 없습니다(이전 검증).

### E4 — 효율 (보조축, 오늘 바로 가능)
- **무엇:** **이미 서빙 중인** Qwen3-32B-FP8(1장)·Coder-30B-A3B-FP8(4장 dp)로 비주얼-토큰 예산(이미지 토큰 수)이 throughput·prefill 길이·dp/pp 스케일에 주는 영향을 측정. 메인의 정확도-효율 Pareto 보조축으로만 씁니다(단독 제출은 약함).

## 3. 최소 완성 논문 (안전장치)

E0가 막혀도 나오는 최소본: **host-loop로 비전 타워 forward 측정 + 컴포넌트 정밀도 민감도 진단(E2)**. 즉 "VLM의 어느 부분이 저정밀에 가장 취약한가"라는 진단은 보장된 기여이고, 복구(E3)·정식 serve는 보너스입니다. 효율 곡선(E4)은 오늘 측정 가능한 보험입니다.

## 4. 제출 위생 (이중맹검)
논문·부록에 들어가는 모든 아티팩트·serve 로그·설정에서 "Furiosa/RNGD/펌웨어" 문자열을 지우고 **"a commercial reduced-precision NPU"** 로 익명화합니다.
