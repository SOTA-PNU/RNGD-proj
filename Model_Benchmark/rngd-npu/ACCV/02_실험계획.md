# 02. 실험 계획 — 무엇을, 어떤 순서로, 어떻게

이 문서는 논문의 실험을 단계별로 무엇을·왜·어떻게(실제 명령어와 코드 골격까지) 하는지 정리한 실행 계획서입니다. 주제 설명은 [01_논문주제.md](01_논문주제.md), 쓰는 코드의 의미는 [03_furiosa-opt_코드해설.md](03_furiosa-opt_코드해설.md)에 있습니다.

## 0. 큰 그림 — 날짜가 아니라 "마일스톤"으로 굴린다

실험을 날짜에 묶지 않고 **단계(마일스톤) M0~M6**로 나눕니다. 각 단계는 그 자체로 "진도"이고, 논문의 완성도는 계단처럼 올라갑니다. 마감이 언제 오든 *그때까지 올라간 가장 높은 단계*를 제출하면 됩니다.

| 단계 | 하는 일 | 끝났다고 보는 기준 | NPU 필요? | vISA 필요? |
|---|---|---|---|---|
| **E0** 정밀도 포맷 측정 (★게이트) | 칩이 강제하는 operand 캐스트가 bf16/int8/fp8 중 무엇인지, 붕괴 주범이 라운딩인지 클립인지 측정 | 포맷·주범 확정 → 헤드라인('스케일' vs '클립') 결정 | O | X |
| **M0** 평가 준비 | ImageNet 검증셋 + 정답 라벨 연결 | CPU(fp32) 정확도가 71.9%로 나옴(연결 정상) | X | X |
| **M1** 붕괴 측정 | 칩에서 학습 모델 top-1이 무너지는 걸 수치로 | 칩 top-1 ≈ 0% + 층별 오차 곡선 | O | X |
| **M2** 원인 진단 | 가중치 쏠림(kurtosis)이 붕괴를 예측함을 보임 | 쏠린 층을 잘 골라냄(AUC) | X | X |
| **M3** 칩 흉내내기 모델 | NPU 계산을 PC에서 똑같이 흉내내는 surrogate | 흉내 결과가 실제 칩과 거의 일치 | X | X |
| **M4** 최적화 복구(흉내 위에서) | 스케일·클립 최적화로 정확도 되살림 | 흉내에서 거의 fp32까지 복구 + 비교실험 | X | X |
| **M5** 진짜 칩에서 복구 | 고친 가중치를 실제 칩에 올려 측정 | 칩 top-1이 실제로 올라감 | O | (b안) O |
| **M6** 확장 | 일반화·혼합정밀도·다른 모델 | 더 강한 버전(다음 학회/저널) | O | O |

**핵심:** M0~M4는 **vISA(furiosa-opt 손코딩) 없이**, 이미 있는 코드와 PC 계산만으로 끝납니다. 그래서 가장 위험한 부분(새 커널 짜기)에 막히지 않고 완결된 논문이 나옵니다. M5부터가 "진짜 칩 위 복구"라는 강한 보너스입니다.

> ⚠️ **E0가 모든 것을 가른다.** 복구 레버가 무엇인지가 칩이 강제하는 정밀도 포맷에 달려 있습니다. **bf16이면** 채널별 스케일은 수학적으로 무효(상대정밀도 스케일 불변)라 헤드라인이 *클립*이 되고, **int8/fp8이면** 스케일+클립 둘 다 의미가 있습니다. 또 우리 레포는 "한 연산당 ~0.23%로 일정(`README_op_support.md`)"과 "감소정밀도에서 누적 폭발(`README_vision_compile.md`)"이 **서로 충돌**합니다 — 0.23%가 누적도 안 되는데 어떻게 100% 단일클래스 붕괴가 나는지는 측정해야 합니다(라운딩 vs 클립/오버플로 vs bf16보다 좁은 캐스트). E0 없이 제목을 못 정합니다.

## 1. 환경 준비 (공통)

```bash
source ~/furiosa/bin/activate                 # 퓨리오사 SDK 2026.2.0 환경
pip install --no-deps torchvision scipy       # 모델 정의·통계용(검증 후 제거 가능)
cd ~/RNGD-proj/Model_Benchmark/rngd-npu/vision_models
furiosa-smi status                            # 빈 NPU 카드 확인 — 보통 npu3이 놂(npu0~2는 LLM이 점유)
```

이미 만들어 둔 도구(그대로 씁니다):
- `compile_vision.py <모델> [--run 3]` — 모델이 칩용으로 컴파일되는지 확인(+실행).
- `run_edf.py compile <모델>` / `run <모델> --npu 3` — 컴파일 결과(EDF)를 저장해 두고, 재컴파일 없이 다시 실행.
- `classify.py <모델> --npu 3 --images a.jpg ... [--reuse-edf 파일.edf]` — **학습된 가중치**로 진짜 사진을 NPU와 CPU에서 분류해 top-5 비교. 지원 모델: `mobilenet_v2`, `efficientnet_b0`.

각 스크립트가 안에서 무슨 일을 하는지는 [03_furiosa-opt_코드해설.md](03_furiosa-opt_코드해설.md) A절을 보세요.

## 2. 단계별 실행 방법

### E0 — 정밀도 포맷·붕괴 주범 측정 (★제일 먼저, NPU 필요)
- **무엇:** 칩이 곱하기 전에 operand를 **어떤 포맷으로 강제로 깎는지**(bf16인지, int8인지, fp8e4m3인지)와, 붕괴를 만드는 게 **라운딩**인지 **클립/오버플로**인지 측정합니다.
- **왜:** 이게 헤드라인을 정합니다. bf16이면 스케일은 무효라 *클립*만 헤드라인이 될 수 있고, int8/fp8이면 스케일+클립 둘 다 유효합니다. 또 "0.23% 일정"과 "누적 폭발"의 모순(위 경고)을 측정으로 해소해야 리뷰어(특히 Lu)의 첫 공격을 막습니다.
- **어떻게:**
  1. 컴파일된 EDF/cast-engine 노드를 들여다봐 실제 캐스트 타입을 확인(가능하면).
  2. PC surrogate를 **포맷별로**(bf16/int8/fp8) 만들어, 어느 포맷이 실제 칩의 단일클래스 붕괴와 argmax를 재현하는지 맞춰 봅니다(아래 M3와 연결).
  3. 같은 입력에서 **클립만 끈 버전 vs 라운딩만 끈 버전**을 surrogate로 비교해 주범을 가립니다.
- **게이트:** 포맷·주범이 확정되면 → M4 헤드라인을 '스케일'/'클립'/'둘 다'로 확정. 미측정 상태로는 제목을 고정하지 않습니다.

### M0 — 평가 준비 (NPU 불필요)
- **무엇:** ImageNet-1k 검증셋(5만 장)과 정답 라벨을 준비하고, 모델 출력 번호(0~999)를 정답과 올바로 연결합니다.
- **왜:** 라벨 연결이 틀리면 모든 정확도 숫자가 조용히 틀어집니다. 먼저 CPU에서 **fp32 정확도가 알려진 값(MobileNetV2 71.9% / EfficientNet-B0 77.7%)** 으로 나오는지 확인해 연결이 맞는지 검증합니다.
- **어떻게:** `classify.py`의 기존 함수 재사용.
```python
from classify import make_model, preprocess     # 모델 로드 + 전처리 함수 그대로 사용
m, w = make_model("mobilenet_v2"); cats = w.meta["categories"]   # 1000개 라벨 순서
# 정확도 = 평균( m(preprocess(경로,w)).argmax(-1) == 정답라벨 )  → 71.9% 나오면 통과
```

### M1 — 붕괴 측정 (E1, NPU 필요)
- **무엇:** 학습 모델을 칩에 올려 top-1이 무너지는 걸 "사진 몇 장"이 아니라 "수천 장"으로 보입니다.
- **어떻게(빠른 재현):**
```bash
python classify.py mobilenet_v2 --npu 3 --images /tmp/dog.jpg /tmp/cat.jpg
# NPU top-1이 전부 한 클래스("window screen")로 나오면 붕괴 확인
```
- **어떻게(수치화):** `classify.py`를 검증셋 루프로 확장합니다. 컴파일(`cm`)은 1번만 하고, 사진마다 `cm(x.to(dev), device=dev)`로 추론해 NPU·CPU top-1/top-5를 모읍니다. 층별로 NPU와 CPU 출력 차이(상대오차)를 재면 "어느 층부터 망가지는지" 보입니다(forward hook 사용).
- **다중 아키텍처(중요 — "CNN 낡았다" 방어, 01번 §7):** 컴파일 가능성을 **먼저** 확인하고 역할을 나눕니다(`classify.py`의 `REG`에 모델 추가 + `compile_vision.py <모델>`로 점검).
  - **ConvNeXt-T(주연):** 현대 CNN이라 "낡았다"를 반박하면서 7×7 depthwise conv가 heavy-tailed라 가중치 진단을 살립니다. 풀링 없음·strided-conv 다운샘플·LayerNorm→Linear로 끝나 컴파일 유망(미검증→`compile_vision.py convnext_tiny` 먼저).
  - **DeiT-S(제2 결과):** ViT 일반성. matmul·softmax·LayerNorm·GELU 지원·풀링 없음·Linear 헤드라 유망(미검증). 붕괴는 conv가 아니라 Linear/attention에서 옴 → conv=matmul 통합으로 설명.
  - **MobileNetV2·EfficientNet-B0(검증된 대조군):** 이미 칩 붕괴 실측.
  - **MobileViT-S/EfficientFormer-L1(조건부 보너스):** fold/unfold·풀링 다운샘플·reparam이 컴파일 막을 수 있음 → 되면 'conv·linear 동시 붕괴' 별, 안 되면 future work(서사 의존 0).
  - ⚠️ ConvNeXt·DeiT 컴파일 시 `constant_pad_nd`(미지원)·8-타일(Lane≤8) 위반이 끼면 그래프가 쪼개질 수 있으니 컴파일 로그를 확인합니다.

### M2 — 원인 진단 (E3, NPU 불필요)
- **무엇:** "가중치가 쏠릴수록 그 층이 더 망가진다"를 수치로 증명하고, 쏠림만 보고 망가질 층을 미리 맞히는 예측기를 만듭니다.
- **어떻게:**
```python
from scipy.stats import kurtosis
# conv 가중치 W: [출력채널, 입력채널, 높이, 너비]
k = kurtosis(W.reshape(W.shape[0], -1).numpy(), axis=1)   # 출력채널별 쏠림 수치
# k(쏠림) 와 M1의 층별 오차의 순위상관(Spearman), 망가진 층 분류 정확도(AUC)
```

### M3 — 칩 흉내내기 모델 Q_npu (E2/E5, NPU 불필요)
- **무엇:** NPU의 계산(입력을 bf16으로 깎고 → f32로 넓게 더하기)을 PC에서 똑같이 흉내내는 함수 `Q_npu`를 만듭니다.
- **왜:** 칩을 매번 쓰지 않고 PC에서 빠르게 수천 번 실험(스케일 바꿔 보기)하려고요. 단, 흉내가 실제 칩과 맞는지 꼭 검증해야 합니다.
- **어떻게:**
```python
cast = E0_format               # ★ bf16 하드코딩 금지 — E0가 정한 포맷(bf16/int8/fp8e4m3)
W_q = quantize_cast(W, cast)   # E0 포맷으로 깎았다 되돌리기 = 칩의 정밀도 손실 흉내
X_q = quantize_cast(X, cast)
y   = conv(W_q, X_q)           # 더하기는 f32(넓은 그릇)
# y의 argmax가 실제 칩 결과와 같은 비율을 보고, 라운딩/클립을 칩에 맞춰 보정
```
- **함정 방지:** "내가 만든 흉내를 내가 검증"하면 의미가 없습니다. **다른 데이터(held-out) + 다른 모델**에서도 흉내가 칩을 맞히는지 확인합니다. 또 surrogate는 **E0가 정한 포맷이 실제 단일클래스 붕괴를 재현**할 때만 신뢰합니다(bf16을 가정하지 않습니다).

### M4 — 최적화 복구 (E4, NPU 불필요)
- **무엇:** `Q_npu` 위에서 채널별 스케일 d와 클립 t를 최적화해 정확도를 되살립니다.
- **어떻게:**
  1. 출발값(closed-form): `d_k = max|W[:,k]|^a / max|X[:,k]|^(1-a)` (SmoothQuant식). `a`는 쏠림(kurtosis)으로 정합니다.
  2. `KL(정밀한 답 ‖ Q_npu의 답)`이 작아지게 d·t를 조금씩 고칩니다(coordinate descent).
  3. d를 가중치에 접어 넣고(인접 층 보정) **정밀계산 결과가 안 변하는지 assert**로 확인 + 튀는 값 클립.
- **비교실험(ablation):** 클립만 / 스케일만 / 둘 다, 쏠림 기반 `a` vs 고정 `a=0.5`, 보정에 쓰는 사진 수 1/8/32/128장.
- **스케일-불변 반증 테스트:** E0가 bf16이라면, **순수 per-channel 스케일은 복구 못 하고 클립만 복구함**을 보여 헤드라인을 '클립 중심'으로 정합니다. int8/fp8이면 스케일+클립 둘 다 효과 → 새로움은 '닫힌 컴파일러+구조 일반성'으로.
- **DFQ 구분 ablation(필수 — "DFQ 재탕" 반박 차단):** Nagel의 DFQ(ICCV'19)는 ReLU 양의 스케일 등변성에 기대 MobileNetV2에 가중치 등화 fold를 이미 했습니다(우리 대조군과 같은 모델). **DFQ가 ConvNeXt의 GELU/ReLU6 + 닫힌 캐스트 격자에서 깨지는 반면, 우리의 '측정된 정밀도모델에 최적화한 fold'는 복구함**을 실측으로 보여 산문이 아니라 데이터로 차별화합니다.

### M5 — 진짜 칩에서 복구 (★중요 갈림길)
- **무엇:** M4에서 고친 모델을 실제 칩에 올려 정확도가 정말 오르는지 봅니다.
- **어떻게:**
```bash
# 고친 가중치 모델을 그대로 컴파일·실행
python classify.py mobilenet_v2 --npu 3 --images /tmp/dog.jpg ...
# 빠른 비교: EDF를 한 번만 저장하고, 설정마다 가중치만 갈아끼워 재컴파일 0초
python run_edf.py compile mobilenet_v2
python classify.py mobilenet_v2 --npu 3 --reuse-edf mobilenet_v2.edf --images ...
```
- **갈림길(GO/NO-GO):** 칩 정확도가 의미 있게 오르면 → "칩 위 복구" 논문(강함). 그래도 ~0%면 → "원인은 입력 깎기(operand-cast)에 있다"는 발견 + 흉내(M4) 복구로 방향 전환. **어느 쪽이든 논문은 성립합니다.**

## 3. 실험 한눈에 (표)

| # | 실험 | 보는 것 | 어디서 | 보장 여부 |
|---|---|---|---|---|
| E0 | 정밀도 포맷·붕괴 주범 측정 (★게이트) | 캐스트 포맷·라운딩 vs 클립 | 칩+PC | 보장 |
| E1 | 붕괴 측정(ConvNeXt-T 주연 + 대조군) | top-1/5 + 층별 오차 | 칩 vs CPU | 보장 |
| E2 | 흉내 모델 정확도 | 흉내가 칩과 일치율 | PC vs 칩 | 보장 |
| E3 | 쏠림 진단 | kurtosis ↔ 오차 상관·AUC | PC | 보장 |
| E4 | 최적화 복구 | 복구 top-1 + 비교실험 | PC(+칩) | 보장 |
| E5 | 입력깎기 vs 더하기 오차 분해 | 어느 쪽이 주범인지 | PC | 보장 |
| E6 | 정밀도 모드(bf16 vs int8) | 정밀도별 정확도 | 칩/흉내 | 보장 |
| E7 | 일반화(흉내 설정 바꿔보기) | 한 칩 버그가 아님 | PC | 보장 |
| E1b | 구조 일반화: ViT(DeiT-S/vit_b_16) 붕괴·복구 | ViT top-1/5 + 복구 | 칩 vs CPU | 조건부(컴파일 가능 시) |
| E8 | (보너스) vISA로 칩에서 복구 | 직접 정밀도 통제 | vISA | 후속 |

비교 기준선: fp32(최고), 무보정(최저), 단일 스케일, SmoothQuant(a=0.5), AWQ, 클립만, **DFQ(Nagel ICCV'19 — 같은 모델 가중치 등화, 우리와 가장 가까운 선행연구)**, nuLSQ(전례로 인용).

## 4. 막혀도 나오는 최소 논문 (안전장치)

밤새 노력해도 못 바꾸는 위험이 셋 있습니다: ① 칩에서 복구가 얼마나 될지(물리), ② 닫힌 컴파일러가 우리가 접어 넣은 스케일을 무시할 가능성, ③ 새 vISA 커널이 닫힌 컴파일러를 통과할지.

그래서 **vISA를 하나도 안 쓰고도** 완결되는 논문을 항상 확보합니다: 칩 위 붕괴 측정(M1) + 쏠림 진단(M2) + 칩에 맞춘 흉내 모델(M3) + 스케일·클립 최적화로 흉내에서 복구(M4). 칩 복구(M5)와 vISA(E8)는 전부 보너스입니다.
