# 타일링

> [!WARNING]
> **WIP**: 이 장은 작성 중이다. 내용은 향후 릴리스에서 추가된다.

타일링은 큰 텐서를 온칩 메모리에 들어가는 작은 타일로 쪼갠다.
온칩 용량이 지배적인 제약이다. 텐서가 [VRF 용량](../quick-start.md#vector-register-file-vrf)(슬라이스당 8KB)이나 [DM 용량](../moving-tensors/memory-performance.md)을 넘으면 여러 회차에 걸쳐 처리해야 한다.

## 타일링을 쓰는 경우


다음 조건 중 하나 이상이 성립할 때 타일링을 적용한다(여러 조건이 함께 성립하는 경우가 많다).
- 텐서 차원이 하드웨어 한 번의 패스에 들어가는 크기를 넘을 때:
  차원 크기를 [Memory Performance](../moving-tensors/memory-performance.md)의 DM 용량 표와 비교한다.
- 적재한 데이터를 재사용해 메모리 대역폭을 최적화해야 할 때:
  같은 데이터를 여러 연산에 걸쳐 두 번 이상 fetch 하는지 확인한다.
- 연산을 공간이 아니라 시간에 걸쳐 분산해야 할 때:
  공간 차원은 이미 완전히 분산되었으나 타일 단위 루프가 필요한 경우에 사용한다.

## 기본 타일링 패턴

기본 타일링 패턴은 하드웨어 한 번의 패스에 담기에는 너무 크지만 연산 구조 자체는 단순한 텐서를 다룬다.
타일 크기가 나머지 결정을 좌우한다. 타일 크기는 VRF/DM 에 들어가야 하고, 정렬 제약(32바이트 flit)을 만족해야 하며, fetch 와 연산을 겹칠 경우 더블 버퍼링 여유를 남겨야 한다.
유효한 타일 크기가 정해지면 실행은 다음 순서로 진행된다. (1) 바깥 차원에서 타일 단위로 순회하고, (2) 각 타일을 HBM 에서 DM 으로 fetch 하고, (3) 연산을 수행하고, (4) 부분 결과를 누적한 뒤 다시 기록한다.
