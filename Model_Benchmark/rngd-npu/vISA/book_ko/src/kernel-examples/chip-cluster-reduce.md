# Chip/Cluster 리듀스

chip/cluster 축약(리듀스)은 리듀스 축이 `Chip` 또는 `Cluster` 매핑 차원에 걸칠 때 서로 다른 처리 유닛에 존재하는 부분 결과를 합친다.


chip/cluster 리듀스를 구현하는 주요 연산은 AllReduce 와 ReduceScatter 두 가지다.
둘 다 Switch Engine 연산(클러스터 안 슬라이스 간 데이터 재분배용)과 Vector Engine 이항 연산(실제 리듀스 계산용)을 조합한다.


## 클러스터 안에서의 전체 텐서 리듀스

클러스터나 칩 경계를 넘기 전에도, Contraction Engine 과 [Inter-Slice Reducer](../computing-tensors/vector-engine/inter-slice-reducer.md) 는 이미 한 클러스터 안에서 상당한 크기의 텐서를 단일 스칼라로 접을 수 있다.
`m![A]::SIZE = 65,536` 인 `m![A]` 에 대한 완전한 reduce-add 는 세 리듀스 단계(Packet, Time, 슬라이스 수준)를 모두 쌓아 약 296 사이클에 단일 스칼라를 만든다.

매핑은 `A` 를 세 단계에 나눈다.

- **`Slice = m![A / 256]`**: 256 개 슬라이스가 병렬로 처리한다.
- **`Time = m![A / 32 % 8]`**: 슬라이스마다 8 회의 시간 반복.
- **`Packet = m![A % 32]`**: 32 개 원소를 공간적으로 리듀스한다.

리듀스는 다음과 같이 나뉜다.

| 단계 | 리듀스되는 축 | 메커니즘 | 사이클 |
|-------|--------------|-----------|--------|
| Packet | `A % 32` | [Packet Reducer](../computing-tensors/contraction-engine/packet-reducer.md) 트리 (깊이 5) | 5 |
| Time | `A / 32 % 8` | [Time Reducer](../computing-tensors/contraction-engine/time-reducer.md) 누산기 (8 회 반복) | 8 |
| 슬라이스 수준 | `A / 256` | [Inter-Slice Reducer](../computing-tensors/vector-engine/inter-slice-reducer.md) | 256 |

- 각 슬라이스는 `A / 256` (256) 개 원소를 처리한다.
- 슬라이스 안에서 트리가 `A % 32` 개 원소를 리듀스한다(`bf16` 은 5 사이클).
- 시간 축 `A / 32 % 8` 은 버퍼가 누적하는 8 개 flit 으로 도착한다.
- 슬라이스 내 리듀스가 끝나면(~40 사이클) 256 개의 부분 결과가 슬라이스들에 걸쳐 존재한다.
- [Inter-Slice Reducer](../computing-tensors/vector-engine/inter-slice-reducer.md) 가 이 256 개 슬라이스 결과를 리듀스한다(256 사이클).
- **합계**: 65,536 개 원소를 단일 스칼라로 리듀스하는 데 ~296 사이클.


## `ReduceScatter`

`ReduceScatter` 는 chip/cluster 축에 분산된 데이터를 리듀스하면서 결과를 분배해 각 칩이 일부를 갖게 한다.
이 연산은 리듀스와 결과 분배가 한 단계에 모두 필요할 때 유용하다.

### 예제: Add 를 쓰는 4-chip `ReduceScatter`

이 예제는 데이터가 한 차원(`A`)으로 분할되어 있으나 다른 차원(`B`)을 따라 리듀스해야 할 때 칩 간 리듀스를 수행하는 방법을 보여준다.
각 칩은 자신에게 할당된 `A` 값에 대한 모든 `B` 값의 데이터를 갖지만, 목표는 각 `B` 마다 모든 `A` 값을 합하는 것이다.

**입력:**
총 16 개 원소를 갖는 2D 텐서 `[A=4, B=4]` 가 4 개 칩에 분산되어 있다:
- **모양**: `[A=4, B=4]` - 총 16 개 원소
- **데이터 타입**: `i8` (8비트 부호 있는 정수)
- **저장소**: 각 칩의 SRAM
- **분산**: `In = {chip: A, slice: 256, element: B}`
  - Chip 0 소유: `(A=0, B=0)`, `(A=0, B=1)`, `(A=0, B=2)`, `(A=0, B=3)` - A=0 에 대한 모든 B 값
  - Chip 1 소유: `(A=1, B=0)`, `(A=1, B=1)`, `(A=1, B=2)`, `(A=1, B=3)` - A=1 에 대한 모든 B 값
  - Chip 2 소유: `(A=2, B=0)`, `(A=2, B=1)`, `(A=2, B=2)`, `(A=2, B=3)` - A=2 에 대한 모든 B 값
  - Chip 3 소유: `(A=3, B=0)`, `(A=3, B=1)`, `(A=3, B=2)`, `(A=3, B=3)` - A=3 에 대한 모든 B 값

**목표:**
결과를 `B` 로 분산된 상태로 유지하면서 `A` 축을 따라 리듀스한다(칩 간 합산):
- **출력 모양**: `[B=4]` - 4 개 원소 (A 차원은 리듀스로 제거)
- **출력 분산**: `Out = {chip: 4, slice: 256, element: 1}`
  - Chip 0 이 가질 값: `(A=0..3, B=0)` 의 합 - B=0 에 대한 모든 A 값의 합
  - Chip 1 이 가질 값: `(A=0..3, B=1)` 의 합 - B=1 에 대한 모든 A 값의 합
  - Chip 2 이 가질 값: `(A=0..3, B=2)` 의 합 - B=2 에 대한 모든 A 값의 합
  - Chip 3 이 가질 값: `(A=0..3, B=3)` 의 합 - B=3 에 대한 모든 A 값의 합

**처리:**

알고리즘은 여섯 단계로 진행한다. 대각선 `Slice` + `ChipShuffle` 패턴으로 중간 텐서 네 개를 만들고, 그것들을 더해 `A` 축을 리듀스한 뒤, 결과를 모든 칩에 브로드캐스트한다.
대각선 패턴은 각 칩이 자신에게 할당된 `B` 값에 필요한 데이터를 받도록 보장한다.
`Slice` (비대칭 슬라이스라고도 한다) 는 특정 칩 위치에서 원소의 부분집합을 추출하는 서브 컨텍스트 연산이다([구현 방법](#implementation-methods-for-each-operation) 참고).
`ChipShuffle` 은 한 칩에서 다른 칩으로 데이터를 옮기는 DMA 기반 재분배 연산이다.

#### 초기 상태

각 칩은 `A` 축을 따라 값 하나를 갖는다:
- Chip 0: `(A=0, B=0)`, `(A=0, B=1)`, `(A=0, B=2)`, `(A=0, B=3)`
- Chip 1: `(A=1, B=0)`, `(A=1, B=1)`, `(A=1, B=2)`, `(A=1, B=3)`
- Chip 2: `(A=2, B=0)`, `(A=2, B=1)`, `(A=2, B=2)`, `(A=2, B=3)`
- Chip 3: `(A=3, B=0)`, `(A=3, B=1)`, `(A=3, B=2)`, `(A=3, B=3)`

#### 1 단계: 텐서 `T0` 생성 - `Slice(0,1,2,3)`

이 단계는 `Slice` 로 각 칩에서 `B` 축을 따라 특정 위치를 선택해 대각선 선택 패턴을 만든다:
- Chip 0: (0,0) 선택
- Chip 1: (1,1) 선택
- Chip 2: (2,2) 선택
- Chip 3: (3,3) 선택

결과 `T0`:
- Chip 0: (0,0)
- Chip 1: (1,1)
- Chip 2: (2,2)
- Chip 3: (3,3)

#### 2 단계: 텐서 `T1` 생성 - `Slice(3,0,1,2)` + `ChipShuffle(1,2,3,0)`

이 단계는 `Slice` 와 `ChipShuffle` 을 조합해 회전된 대각선 패턴을 만든다.
먼저 `Slice` 가 원소를 선택한다:
- Chip 0: (0,3)
- Chip 1: (1,0)
- Chip 2: (2,1)
- Chip 3: (3,2)

그다음 `ChipShuffle(1,2,3,0)` 이 데이터를 재분배해 각 칩이 다른 칩의 데이터를 받게 한다:
- Chip 1 의 데이터가 Chip 0 으로 이동: (1,0)
- Chip 2 의 데이터가 Chip 1 로 이동: (2,1)
- Chip 3 의 데이터가 Chip 2 로 이동: (3,2)
- Chip 0 의 데이터가 Chip 3 로 이동: (0,3)

#### 3 단계: 텐서 `T2` 생성 - Slice(2,3,0,1) + ChipShuffle(2,3,0,1)

이 단계는 또 다른 회전된 대각선 패턴을 만든다.
먼저 Slice 가 위치를 선택한다:
- Chip 0: (0,2) 선택
- Chip 1: (1,3) 선택
- Chip 2: (2,0) 선택
- Chip 3: (3,1) 선택

그다음 ChipShuffle(2,3,0,1) 이 데이터를 재분배해 `T2` 를 만든다:
- Chip 0: (2,0)
- Chip 1: (3,1)
- Chip 2: (0,2)
- Chip 3: (1,3)

#### 4 단계: 텐서 `T3` 생성 - ChipSlice(1,2,3,0) + ChipShuffle(3,0,1,2)

이 단계는 마지막 회전된 대각선 패턴을 만든다.
먼저 Slice 가 위치를 선택한다:
- Chip 0: (0,1) 선택
- Chip 1: (1,2) 선택
- Chip 2: (2,3) 선택
- Chip 3: (3,0) 선택

그다음 ChipShuffle(3,0,1,2) 이 데이터를 재분배해 `T3` 를 만든다:
- Chip 0: (3,0)
- Chip 1: (0,1)
- Chip 2: (1,2)
- Chip 3: (2,3)

#### 5 단계: Vector Engine Add - A 축 리듀스

이 단계는 4 개 텐서를 원소별로 더해 실제 리듀스를 수행한다:
- Chip 0: (0,0) + (1,0) + (2,0) + (3,0)
- Chip 1: (1,1) + (2,1) + (3,1) + (0,1)
- Chip 2: (2,2) + (3,2) + (0,2) + (1,2)
- Chip 3: (3,3) + (0,3) + (1,3) + (2,3)

이 덧셈 후에는 A 축이 리듀스되었으므로 각 칩이 값 하나만 갖는다:
- `Intermediate = { chip: B, slice: 256, element: 1 }`

#### 6 단계: AllGather


이 마지막 단계는 결과를 브로드캐스트해 모든 칩이 완전한 리듀스 출력을 갖게 한다.
각 칩은 Chip 0 부터 Chip 3 까지의 데이터를 모은다:

- `Intermediate = { chip: 4, slice: 256, element: B }`

**출력:**


여섯 단계가 모두 끝나면 각 칩은 리듀스된 결과의 일부를 갖는다:
- **최종 분산**: `Out = {chip: A, slice: 256, element: 4}`
- **Chip 0**: 모든 `(A=*, B=0)` 값의 합을 갖는다
- **Chip 1**: 모든 `(A=*, B=1)` 값의 합을 갖는다
- **Chip 2**: 모든 `(A=*, B=2)` 값의 합을 갖는다
- **Chip 3**: 모든 `(A=*, B=3)` 값의 합을 갖는다

`A` 축은 리듀스되었고(4 개 칩에 걸쳐 합산), 결과는 `B` 값에 따라 칩들에 흩어진다.
이제 각 칩은 자신에게 할당된 `B` 좌표에 대한 모든 `A` 값의 합을 나타내는 원소 하나를 갖는다.

**이 예제가 유용한 이유:**

`ReduceScatter` 는 분산 컴퓨팅에서 자주 함께 나타나는 두 연산을 결합한다:
- **프로세서 간 리듀스**: 여러 칩에 분산된 데이터를 합산·집계한다
- **결과 분배**: 결과를 모든 곳에 복제하는 대신 각 칩이 일부를 받는다

이 패턴은 다음에 필수적이다:
- **분산 행렬곱**: 서로 다른 칩의 부분곱을 리듀스하면서 결과를 분배한다
- **데이터 병렬에서의 그래디언트 집계**: 워커 전체에 걸쳐 그래디언트를 합하되 각 워커가 일부를 보유한다
- **메모리 효율**: 완전한 리듀스 결과를 모든 칩에 저장하지 않는다(AllReduce 와 달리)
- **파이프라인 병렬**: 파이프라인 단계 간 효율적인 통신 패턴을 가능하게 한다

대각선 슬라이싱 패턴이 핵심이다. 각 출력 원소에 필요한 데이터가 리듀스 전에 모든 칩에서 모이도록 보장해 통신 라운드를 최소화한다.


## `AllReduce`

`AllReduce` 는 chip 축에 분산된 데이터를 리듀스해 모든 칩이 동일한 리듀스 결과를 갖게 한다.
`ReduceScatter` 와 달리 `AllReduce` 는 모든 칩이 일부가 아니라 완전한 결과를 갖도록 보장한다.

### 예제: Add 를 쓰는 4-chip `AllReduce`

이는 데이터 병렬 학습 워커 전체에 걸쳐 그래디언트를 평균하는 것 같은 연산에 필수적이다.

**입력:**
`A` 차원에 따라 4 개 칩에 분산된 2D 텐서 `[A=4, B=4]`:
- **모양**: `[A=4, B=4]` - 총 16 개 원소
- **데이터 타입**: `i8` (8비트 부호 있는 정수)
- **저장소**: 각 칩의 SRAM
- **분산**: `In = {chip: A, slice: 256, element: B}`
  - Chip 0 소유: `(A=0, B=0-3)` - A=0 에 대한 4 개 B 값 전부
  - Chip 1 소유: `(A=1, B=0-3)` - A=1 에 대한 4 개 B 값 전부
  - Chip 2 소유: `(A=2, B=0-3)` - A=2 에 대한 4 개 B 값 전부
  - Chip 3 소유: `(A=3, B=0-3)` - A=3 에 대한 4 개 B 값 전부

**목표:**
`A` 축을 따라 리듀스하고 완전한 결과를 모든 칩에 복제한다:
- **출력 모양**: `[B=4]` - 4 개 원소 (A 차원은 합산으로 제거)
- **출력 분산**: `Out = {chip: 4, slice: 256, element: B}`
  - **모든 칩**이 갖는 값: 모든 `(A=0..3, B=0)` 의 합, 모든 `(A=0..3, B=1)` 의 합, 모든 `(A=0..3, B=2)` 의 합, 모든 `(A=0..3, B=3)` 의 합
  - AllReduce 가 끝나면 모든 칩이 동일한 데이터를 갖는다

**처리:**

대각선 Slice+ChipShuffle 로 각 칩에 서로 다른 데이터를 보내는 ReduceScatter 와 달리, AllReduce 는 균일한 ChipShuffle 회전을 써서 모든 칩이 모든 입력을 동일하게 누적하게 한다.
알고리즘은 회전으로 입력 텐서의 4 개 버전을 만든 뒤 전부 더한다:
1. 원본 텐서 `T0` 에 `ChipShuffle` 연산 3 개를 적용해 회전된 버전 3 개(`T1`, `T2`, `T3`)를 만든다
2. Vector Engine 으로 4 개 텐서를 원소별로 더한다
3. 모든 칩이 자신의 로컬 데이터에 같은 덧셈을 수행하므로 어디서나 동일한 결과가 나온다

#### 초기 상태 (`T0`)

각 칩은 A 축을 따라 값 하나를 갖는다:
- Chip 0: (A=0, B=0), (A=0, B=1), (A=0, B=2), (A=0, B=3)
- Chip 1: (A=1, B=0), (A=1, B=1), (A=1, B=2), (A=1, B=3)
- Chip 2: (A=2, B=0), (A=2, B=1), (A=2, B=2), (A=2, B=3)
- Chip 3: (A=3, B=0), (A=3, B=1), (A=3, B=2), (A=3, B=3)

#### 1 단계: 텐서 `T1` 생성 - ChipShuffle(1,2,3,0)

이 단계는 데이터를 칩 한 자리만큼 회전시킨다.
원본 `T0` 에 ChipShuffle(1,2,3,0) 을 적용한다:
- Chip 1 의 데이터가 Chip 0 으로 이동
- Chip 2 의 데이터가 Chip 1 로 이동
- Chip 3 의 데이터가 Chip 2 로 이동
- Chip 0 의 데이터가 Chip 3 로 이동

결과 `T1`:
- Chip 0: (1,0), (1,1), (1,2), (1,3)
- Chip 1: (2,0), (2,1), (2,2), (2,3)
- Chip 2: (3,0), (3,1), (3,2), (3,3)
- Chip 3: (0,0), (0,1), (0,2), (0,3)

#### 2 단계: 텐서 `T2` 생성 - ChipShuffle(2,3,0,1)

이 단계는 데이터를 칩 두 자리만큼 회전시킨다.
원본 `T0` 에 ChipShuffle(2,3,0,1) 을 적용한다:
- Chip 2 의 데이터가 Chip 0 으로 이동
- Chip 3 의 데이터가 Chip 1 로 이동
- Chip 0 의 데이터가 Chip 2 로 이동
- Chip 1 의 데이터가 Chip 3 로 이동

결과 `T2`:
- Chip 0: (2,0), (2,1), (2,2), (2,3)
- Chip 1: (3,0), (3,1), (3,2), (3,3)
- Chip 2: (0,0), (0,1), (0,2), (0,3)
- Chip 3: (1,0), (1,1), (1,2), (1,3)

#### 3 단계: 텐서 `T3` 생성 - ChipShuffle(3,0,1,2)

이 단계는 데이터를 칩 세 자리만큼 회전시킨다.
원본 `T0` 에 ChipShuffle(3,0,1,2) 을 적용한다:
- Chip 3 의 데이터가 Chip 0 으로 이동
- Chip 0 의 데이터가 Chip 1 로 이동
- Chip 1 의 데이터가 Chip 2 로 이동
- Chip 2 의 데이터가 Chip 3 로 이동

결과 `T3`:
- Chip 0: (3,0), (3,1), (3,2), (3,3)
- Chip 1: (0,0), (0,1), (0,2), (0,3)
- Chip 2: (1,0), (1,1), (1,2), (1,3)
- Chip 3: (2,0), (2,1), (2,2), (2,3)

#### 4 단계: Vector Engine Add - A 축 리듀스

이 단계는 4 개 텐서 `T0`, `T1`, `T2`, `T3` 를 더해 실제 리듀스를 수행한다:
- Chip 0: (0,0)+(1,0)+(2,0)+(3,0), (0,1)+(1,1)+(2,1)+(3,1), (0,2)+(1,2)+(2,2)+(3,2), (0,3)+(1,3)+(2,3)+(3,3)
- Chip 1: (1,0)+(2,0)+(3,0)+(0,0), (1,1)+(2,1)+(3,1)+(0,1), (1,2)+(2,2)+(3,2)+(0,2), (1,3)+(2,3)+(3,3)+(0,3)
- Chip 2: (2,0)+(3,0)+(0,0)+(1,0), (2,1)+(3,1)+(0,1)+(1,1), (2,2)+(3,2)+(0,2)+(1,2), (2,3)+(3,3)+(0,3)+(1,3)
- Chip 3: (3,0)+(0,0)+(1,0)+(2,0), (3,1)+(0,1)+(1,1)+(2,1), (3,2)+(0,2)+(1,2)+(2,2), (3,3)+(0,3)+(1,3)+(2,3)

각 칩이 피연산자 순서만 다를 뿐 수학적으로 같은 결과를 계산한다는 점에 주목한다(덧셈은 교환법칙이 성립하므로 순서는 상관없다).
이 단계 후 모든 칩이 동일한 데이터를 갖는다.

**출력:**

AllReduce 가 끝나면 모든 칩이 완전한 리듀스 결과를 갖는다:
- **최종 분산**: `Out = {chip: 4, slice: 256, element: B}`
- **모든 칩이 동일한 데이터를 갖는다**: 각 B 위치에 대한 모든 A 값의 합
  - 모든 칩이 갖는 값: `[sum(A=0..3, B=0), sum(A=0..3, B=1), sum(A=0..3, B=2), sum(A=0..3, B=3)]`

이는 `[A=4] | [B=4]` 를 `[Broadcast=4] | [B=4]` 로 변환하는 것으로 볼 수 있다:
- `A` 축이 리듀스되었다(합산으로 제거)
- 결과가 모든 칩에 브로드캐스트된다(모든 칩이 완전한 결과를 갖는다)

**이 예제가 유용한 이유:**

`AllReduce` 는 분산 머신러닝의 주력 연산이다:
- **데이터 병렬 학습**: 서로 다른 칩의 여러 배치에서 계산한 그래디언트를 평균한다
- **모델 평균화**: 여러 워커의 매개변수 갱신을 결합한다
- **동기화 프리미티브**: 진행하기 전에 모든 칩이 동일한 상태를 갖도록 보장한다
- **전역 통계**: 분산 데이터셋 전체에 걸쳐 평균/최대/최소 같은 지표를 계산한다

주요 특성:
- **대역폭 효율적**: 각 칩은 셔플 연산 3 개에서만 데이터를 받는다(전체 텐서 전송 3 회가 아니다)
- **대칭적**: 모든 칩이 같은 계산을 수행하므로 구현이 단순해진다
- **완전 복제**: 모든 칩이 전체 결과를 갖고 끝나므로 이후 연산을 독립적으로 수행할 수 있다
- **집합 연산의 토대**: 더 복잡한 분산 연산이 AllReduce 위에 세워진다

여기 보인 회전 기반 알고리즘은 2 의 거듭제곱 개수의 칩으로 확장된다. 칩 8 개면 회전 7 회, 칩 16 개면 회전 15 회 식이다.

가능하면 리듀스 축을 `Slice` / `Element` 에 할당하는 편이 낫다(Inter-Slice Reducer / Vector Engine 이 리듀스한다). 칩 간 통신 오버헤드를 피할 수 있기 때문이다.

## 각 연산의 구현 방법

각 chip/cluster 리듀스 연산이 어떤 하드웨어 프리미티브로 매핑되는지 이해하면 성능과 자원 사용 패턴을 예측하는 데 도움이 된다.
비대칭 Slice 와 Shuffle 은 ReduceScatter 에서 쓰인다.
텐서 덧셈은 ReduceScatter 와 AllReduce 양쪽에서 쓰인다.

### 비대칭 Slice

비대칭 slice 는 서브 컨텍스트에서 `stos` (Store to SRAM) 명령을 사용하는 `ParallelCopy` 로 구현된다.
이 방식은 전체 텐서를 이동하지 않고 데이터를 선택적으로 추출하며, 슬라이스 인덱스가 지정한 위치의 원소만 복사한다.
서브 컨텍스트 실행 덕분에 slice 연산이 메인 컨텍스트 계산과 겹칠 수 있어 파이프라인 효율이 유지된다.

### Shuffle

Shuffle 은 칩 내 이동(서로 다른 칩에 연결된 HBM 영역 사이)에는 `DmaCommand` 로, 칩 간 통신에는 `PCIeDmaCommand` 로 구현된다.
HBM 대 HBM 전송 패턴은 칩 로컬 메모리를 거치는 불필요한 왕복을 피하고 데이터를 목적지로 직접 보낸다.
Shuffle 연산은 인터커넥트 패브릭을 통한 칩 간 데이터 이동을 수반하므로 chip/cluster 리듀스에서 주된 비용 요인이며, 데이터 양에 따라 보통 수백에서 수천 사이클이 필요하다.

### 텐서 덧셈

텐서 덧셈은 여러 입력 텐서를 원소별로 결합해 실제 리듀스 계산을 수행한다.
이 연산은 메인 컨텍스트에서 두 단계 방식으로 실행된다. 인터리브드 fetch 가 여러 텐서 인스턴스의 데이터를 파이프라인으로 가져오고, Vector Engine 의 이항 add 연산이 원소별 합산을 수행한다.
인터리브드 fetch 패턴은 피연산자를 번갈아 오는 시간 단계에 제시해 Vector Engine 이 덧셈을 효율적으로 처리하게 하며, 별도의 누적 버퍼가 필요 없게 한다.
이 메인 컨텍스트 실행은 slice 와 shuffle 연산으로 데이터가 적절히 배치된 뒤, 연산 집약적인 리듀스 단계에 최대 처리량을 제공한다.
